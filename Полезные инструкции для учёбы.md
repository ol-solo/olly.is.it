# Техническое
## Сброс прогресса

### Коротко

**Что важно знать?**

- сбросить прогресс можно только со всей темы сразу;
- отдельно сбросить прогресс одного урока из темы – не получится;
- сбросить не до конца пройденную тему тоже не получится;
- можно перепроходить тему сколько угодно раз.

**Как сбросить прогресс?**

- находим нужную тему;
- наводим курсором на закрашенную галочку (показатель прохождения темы);
- нажимаем на появившуюся круглую стрелку;
- в появившемся поп-апе соглашаемся с действием и нажимаем "пройти заново";
- ура, прогресс сброшен, тему можно пройти еще раз!

![image](https://pictures.s3.yandex.net/resources/__2020-10-12__15.38.23_1647879680.png)

![image](https://pictures.s3.yandex.net/resources/__2020-10-12__15.39.03_1647879690.png)

### Подробнее

**Что сбрасывается?**

- Задания, квизы, диалоги, экшн-кнопки.

**А что не сбрасывается?**

- Прочитанная теория в уроке – можно открыть любой не по порядку.
- Проектная работа.

**Где можно сбросить прогресс по теме?**

- Как в платном, так и в бесплатном курсах.
- На карточке курса в Профиле.
- В шторке с оглавлением в Тренажерах.
- В сайдбаре платного курса при чтении теории.

**Ещё немного деталей**

- После поп-апа "пройти заново" перенаправит на первый урок выбранной темы.
- Повторно пройденный урок или тема отмечаются двойной закрашенной галочкой.
- Если в курсе одна тема, то ее заголовок не отображается в оглавлении или сайдбаре и сбросить ее нельзя. Обычно это темы с лонгридами, например, в онбординге.
- Если студент проходит заново тему в освоенном курсе – он остается среди пройденных.
- Если студент не до конца прошел сброшенную тему, но закончил остальные темы в курсе – курс все равно станет пройденным.
- Если студент платного трека прошел тему заново и тут же хочет сделать это еще раз, нужно обновить страницу, чтобы в черном сайдбаре слева появилась круглая стрелка сброса.

# Создание виртуального окружения для локальной работы

## 1.Введение

В этой теме вы узнаете, как установить необходимые для курса программы на ваш компьютер.

Можно ничего не устанавливать и использовать только интернет-браузер, нашу платформу и несколько сторонних сервисов. Однако мы рекомендуем в какой-то момент курса, когда вы почувствуете, что готовы, локально установить программы. Умение работать с данными на вашем компьютере поможет выполнять тестовые задания или осуществлять сторонние проекты. И, конечно, будет полезно на самой работе.

Лучше всего установить программы в конце прохождения первого модуля. Однако, если вам нужно будет больше времени на задания, вы сможете вернуться к тому, чтобы настроить локальную работу с Python в любое время в последующем.

Есть разные инструменты для локальной работы. Мы рекомендуем установить дистрибутив Anaconda и в этой теме расскажем, как это сделать. Anaconda позволит изолировать окружение ваших проектов от системы без сложных настроек.

## 2.Установка Anaconda и создание виртуального окружения на Windows
В этом уроке вы узнаете, как установить дистрибутив Anaconda на свой компьютер с операционной системой Windows. Если у вас другая операционная система, выберите соответствующий урок.

Anaconda уже включает в себя интерпретатор Python. С помощью Anaconda вы сможете создавать виртуальные окружения на своём компьютере — это изолированные «коробки» с Python и различными библиотеками, например pandas или seaborn. В разных окружениях у вас могут быть установлены различные версии одной библиотеки — они не будут конфликтовать друг с другом.

Перед установкой убедитесь, что у вас на компьютере ещё не установлены Python или Anaconda. Также проверьте, чтобы у вас на диске было минимум 10 гигабайт свободного пространства. С нехваткой места связана ошибка `…no space left on device`, возникающая в процессе установки.

Обратите внимание, что видео в конце каждого шага воспроизводят описанные текстом инструкции. Эти видео помогут вам лучше разобраться с процессом установки.

### Шаг 1. Скачайте дистрибутив

Откройте [страницу загрузки Anaconda](https://anaconda.com/download), перейдите в нижнюю часть страницы и скачайте установщик с графическим интерфейсом (… Graphical Installer) для операционной системы Windows.

Выберите установщик с соответствующей разрядностью. На Windows разрядность системы указана в «Характеристиках устройства».

![](https://pictures.s3.yandex.net/resources/image_1698073833.png)

❗ Пользователям Windows 7 x86/x64 и всем, кто столкнулся с ошибкой в процессе установки Anaconda, нужно установить Anaconda3-5.3.1. Перейдите по ссылке [https://repo.anaconda.com/archive/](https://repo.anaconda.com/archive/) и скачайте версию установщика `Anaconda3-5.3.1-Windows-x86_64.exe`.

### Шаг 2. Откройте загруженный файл и выполните установку

- Дважды кликните левой кнопкой мыши по загруженному файлу в разделе загрузок браузера или в папке в «Проводнике».
- Нажмите кнопку Next.
- Выберите путь на диске для установки или оставьте его по умолчанию. Нажмите кнопку Next.
- Обязательно поставьте галочку в пункте **Add Anaconda3 to my PATH environment variable**. Нажмите кнопку Install. Если поле с галочкой неактивно, пропустите этот шаг.
- Дождитесь завершения установки. Это может занять продолжительное время — видео ниже ускорено. Затем нажмите кнопку Next.
- Повторно нажмите кнопку Next.
- Снимите галочки с пунктов Launch Anaconda Navigator и Getting Started with Anaconda Distribution. Нажмите кнопку Finish. Установка завершена.

### Шаг 3. Запустите терминал Anaconda Prompt

После установки вы сможете запустить терминал Anaconda Prompt — в нём выполняются текстовые команды для управления виртуальными окружениями.

- Введите в меню «Пуск» слово `prompt`.
- Из предложенных вариантов выберите `Anaconda Prompt`.
- В появившемся окне терминала есть поле для ввода команд. Слева от него в круглых скобках написано `base` — это название виртуального окружения по умолчанию. В нём уже есть некоторые библиотеки для анализа данных. Но мы создадим новое виртуальное окружение, которое будет полностью совпадать с виртуальным окружением Python на платформе Яндекс Практикума.

Заметьте, что в терминале не работает переключение курсора с помощью мыши. Вам понадобятся стрелочки на клавиатуре для перемещения курсора и клавиша `Enter` для выполнения команд.

Если вы ошиблись с командой, не пытайтесь удалить её в терминале. Просто напишите исправленную команду заново в новой появившейся строке. Небольшой лайфхак: чтобы не набирать последнюю команду в терминале заново, можно нажать клавишу со стрелочкой вверх на клавиатуре — она восстановит последнюю введённую строку.

Обратите внимание на язык ввода: некоторые русские (кириллические) символы легко перепутать с английскими (латинскими) символами.

### Шаг 4. Скачайте файл с описанием окружения и скопируйте путь

- Для создания виртуального окружения скачайте файл по ссылке ниже. Этот файл содержит информацию о библиотеках, их версиях и названии окружения. Пожалуйста, не меняйте название файла — `da_practicum_env.yml`. Если файл сохранился с другим названием, либо переименуйте его, либо используйте другое название и в последующих командах.

- Зайдите в папку с загруженным файлом через «Проводник» и скопируйте путь до файла. Удерживая клавишу `Shift`, нажмите правой клавишей мыши на скаченный файл с расширением `.yml`. В появившемся контекстном меню выберите пункт «Копировать как путь».
    

### Шаг 5. Создайте виртуальное окружение

- Вернитесь в терминал Anaconda Prompt и напишите в нём команду

```
conda env create -f путь 
```

, где `путь` — это скопированный ранее путь до файла `da_practicum_env.yml`.

Например,

```
conda env create -f C:\Users\myuser\Downloads\da_practicum_env.yml 
```

При копировании путь к файлу может сохраниться с кавычками. Если в пути к файлу есть символы пробела, то оставить кавычки нужно обязательно. Если нет — кавычки можно убрать. Вставить скопированный путь в поле терминала можно, например, кликнув правой клавишей мыши внутри терминала.

- Нажмите клавишу `Enter` для ввода команды.
- Дождитесь завершения создания окружения и установки библиотек. Это может занять продолжительное время, видео ниже ускорено.

**Возможная ошибка**

При установке окружения из файла может возникнуть ошибка **InvalidArchiveError:**

В этом случае выполните в терминале команду

```

```

и попробуйте снова создать окружение из файла `da_practicum_env.yml`.

### Шаг 6. Активируйте окружение

На предыдущем шаге вы создали виртуальное окружением с именем `practicum`. Теперь его можно активировать, чтобы использовать библиотеки из него.


Виртуальное окружение активировано. В круглых скобках слева от пути должно быть написано `practicum`.

**Возможная ошибка: виртуальное окружение создалось с другим названием**

Если окружение не активируется, то проверьте список всех установленных виртуальных окружений — возможно, оно создалось с другим названием. Вывести весь список виртуальных окружений можно командой

```

```

Если это так, то используйте при активации соответствующее название окружения.

## 3.Установка расширения toc2 для оглавлений на Windows

### Зачем это нужно

Проекты, выполняемые в Jupyter Notebook, могут быть достаточно объёмными: они включают код, пояснительные тексты, графики и т. д.

Чтобы улучшить навигацию по тетрадям, часто вручную создают оглавление с гиперссылками — это требует определённых усилий.

Расширение `toc2` для Jupyter Notebook позволяет забыть об этой проблеме: оглавление и навигация между различными частями проекта формируются автоматически на основе заголовков, созданных с помощью языка разметки Markdown. Расширение `toc2` установлено в Jupyter Notebook на платформе Яндекс Практикума.

Если вы выполняете проекты не на платформе, а у себя на компьютере, то может быть полезно установить этот плагин локально. Однако это необязательно. Модуль Jupyter Nbextensions, через который устанавливаются плагины, достаточно капризный. Пользователи часто сталкиваются с различными ошибками совместимости — и их причин очень много. Если при установке расширения `toc2` возникли проблемы и вы не можете их решить, то просто пропустите этот шаг.

Мы расскажем два способа работы с оглавлением на вашем компьютере.

### Способ 1. Установка `toc2` в Jupyter Notebook

❗ На Windows перед началом работы установите Microsoft Visual C++, который входит в пакет [Microsoft Build Tools](https://visualstudio.microsoft.com/ru/visual-cpp-build-tools/). Загрузите установщик и установите все инструменты, которые входят в этот пакет. Обратите внимание, что установка всех компонентов займёт много пространства на вашем диске. Без Microsoft Visual C++ возможны ошибки при установке остальных библиотек.

1. Запустите командную строку Anaconda Prompt, её можно найти в меню «Пуск» в поиске, как вы делали в предыдущем уроке. Или откройте «Все приложения» → Anaconda3 (64-bit) → Anaconda Prompt (Anaconda3).
    
    Активируйте виртуальное окружение командой
    
    ```
    conda activate practicum 
    ```
    
2. Скорее всего, после предыдущего шага у вас будет установлена одна из последних версий Jupyter Notebook. Они не поддерживают модуль Jupyter Nbextensions. Поэтому придётся установить более старую версию. Выполните в терминале команду
    
    ```
    pip install jupyter notebook==6.4.0 --user 
    ```
    
    **Возможная ошибка**
    
    Если возникнет ошибка, связанная с модулем `pip`, то попробуйте выполнить команду
    
    ```
    pip3 install jupyter notebook==6.4.0 --user 
    ```
    
3. Теперь установите Jupyter Nbextensions с помощью команды
    
    ```
    conda install -c conda-forge jupyter_contrib_nbextensions 
    ```
    
    В процессе установки вам будет предложено подтвердить установку (_Proceed?…_). Для этого введите латинский символ `y` и нажмите клавишу `Enter`.
    
4. Затем выполните команду
    
    ```
    jupyter contrib nbextension install --user 
    ```
    
5. Попытайтесь запустить Jupyter Notebook командой
    
    ```
    jupyter notebook 
    ```

Проекты с прежним оформлением могут некорректно отображаться после установки `toc2`:

- автоматическая нумерация наложится на номера в заголовках,
- ссылки в содержании перестанут работать.

Первой проблемой можно пренебречь: она затронет читателей проекта, только если у них установлено такое же расширение.

Содержание лучше исправить перед публикацией портфолио. Добавьте автоматическое содержание с помощью `toc2`. Такое содержание будет работать на любых компьютерах: с `toc2` и без.

## 4.Установка Anaconda и виртуального окружения на MacOS
В этом уроке вы узнаете, как установить дистрибутив Anaconda на свой компьютер с операционной системой MacOS. Если у вас другая операционная система, выберите соответствующий урок.

Anaconda уже включает в себя интерпретатор Python. С помощью Anaconda вы сможете создавать виртуальные окружения на своём компьютере — это изолированные «коробки» с Python и различными библиотеками, например pandas или seaborn. В разных окружениях у вас могут быть установлены различные версии одной библиотеки — они не будут конфликтовать друг с другом.

Перед установкой убедитесь, что у вас на компьютере ещё не установлены Python или Anaconda. Также проверьте, чтобы у вас на диске было минимум 5 гигабайт свободного пространства. С нехваткой места связана ошибка `…no space left on device`, возникающая в процессе установки.

Обратите внимание, что видео в конце каждого шага воспроизводят описанные текстом инструкции. Эти видео помогут вам лучше разобраться с процессом установки.

### Шаг 1. Скачайте дистрибутив

Откройте [страницу загрузки Anaconda](https://anaconda.com/download), перейдите в нижнюю часть страницы и скачайте установщик с графическим интерфейсом (… Graphical Installer) для операционной системы MacOS. Выберите версию **64-Bit Graphical Installer**, если у вас устройство на MacOS с процессором Intel. Выберите версию **64-Bit (M1) Graphical Installer**, если у вас устройство на MacOS с процессорами M1 или M2. Узнать свою версию процессора можно в пункте «Об этом Mac». Его можно выбрать в контекстном меню после нажатия на кнопку с яблоком в левом верхнем углу экрана.

### Шаг 2. Откройте загруженный файл и выполните установку

- Дважды кликните левой кнопкой мыши по загруженному файлу в разделе загрузок браузера или в папке загрузок в Finder.

### Шаг 3. Запустите терминал

После установки запустите терминал MacOS — в нём выполняются текстовые команды для управления виртуальными окружениями.

**Способ 1.**

Нажмите клавишу `F4`. В появившемся экране со всеми программами наверху есть окно поиска. Введите в нём `terminal` или `терминал`. Нажмите на иконку программы Terminal. На экране появится новое окно с терминалом.

Обратите внимание на язык ввода: некоторые русские (кириллические) символы легко перепутать с английскими (латинскими) символами.

## 5.Установка расширения toc2 для оглавлений на MacOS

### Зачем это нужно

Проекты, выполняемые в Jupyter Notebook, могут быть достаточно объёмными: они включают код, пояснительные тексты, графики и т. д.

Чтобы улучшить навигацию по тетрадям, часто вручную создают оглавление с гиперссылками — это требует определённых усилий.

Расширение `toc2` для Jupyter Notebook позволяет забыть об этой проблеме — оглавление и навигация между различными частями проекта формируются автоматически на основе заголовков, созданных с помощью языка разметки Markdown. Расширение `toc2` установлено в Jupyter Notebook на платформе Яндекс Практикума.

Если вы выполняете проекты не на платформе, а у себя на компьютере, то может быть полезно установить этот плагин локально. Однако это необязательно. Модуль Jupyter Nbextensions, через который устанавливаются плагины, достаточно капризный. Пользователи часто сталкиваются с различными ошибками совместимости — и их причин очень много. Если при установке расширения `toc2` возникли проблемы и вы не можете их решить, то просто пропустите этот шаг.

Мы расскажем два способа работы с оглавлением на вашем компьютере.

### Способ 1. Установка `toc2` в Jupyter Notebook

1. На **MacOS** запустите терминал с помощью утилиты Spotlight или экрана всех приложений по нажатию F4. Вы делали это в предыдущем уроке.
    
    Активируйте в терминале виртуальное окружение командой
    
    ```
    conda activate practicum 
    ```
    
2. После предыдущего урока у вас будет установлена одна из последних версий Jupyter Notebook. Они не поддерживают модуль Jupyter Nbextensions. Поэтому придётся установить более старую версию Notebook. Выполните в терминале команду
    
    ```
    pip install jupyter notebook==6.4.0 --user 
    ```
    
    **Возможная ошибка**
    
    Если возникла ошибка, связанная с модулем `pip`, попробуйте выполнить команду
    
    ```
    pip3 install jupyter notebook==6.4.0 --user 
    ```
    
3. Теперь установите Jupyter Nbextensions с помощью команды
    
    ```
    conda install -c conda-forge jupyter_contrib_nbextensions 
    ```
    
    В процессе установки вам будет предложено подтвердить установку (_Proceed?…_). Для этого введите латинский символ `y` и нажмите клавишу `Enter`.
    
4. Чтобы убедиться, что все необходимые статические файлы были созданы, выполните команду
    
    ```
    jupyter contrib nbextension install --user 
    ```
    
5. Попытайтесь запустить Jupyter Notebook командой
    
    ```
    jupyter notebook 
    ```
    
    Если произошла ошибка `Module notebook.app not found`, то модуль `notebook.app` в указанном скрипте нужно переименовать в `notebook.notebookapp`. Это можно сделать вручную. В тексте ошибки вы найдёте путь к файлу `jupyter-notebook` со скриптом. Найдите этот файл в Finder, перейдя в соответствующую папку.
    
    Это можно сделать, выбрав вверху экрана в системном меню Finder пункт «Переход», а в нём — подпункт «Переход к папке». В появившемся окне нужно указать путь к папке с файлом `jupyter-notebook`, указанный в тексте ошибки из терминала.
    
    Откройте файл `jupyter-notebook` в текстовом редакторе, например в стандартном TextEdit. Замените строку
    
    ```
    from notebook.app import main 
    ```
    
    на
    
    ```
    from notebook.notebookapp import main 
    ```
    
    После этого сохраните файл: в системном меню TextEdit нужно выбрать «Файл» → «Сохранить». Теперь попробуйте ещё раз запустить Jupyter Notebook в терминале.
    
    Если после этого при попытке запуска Jupyter Notebook у вас возникла ошибка `warn() missing 1 required keyword-only argument: stacklevel` или похожая на неё, попробуйте выполнить две команды в терминале при активированном виртуальном окружении:
    
    ```
    pip uninstall traitlets
    pip install traitlets==5.9.0 
    ```
    
    Попробуйте запустить Jupyter Notebook ещё раз в терминале.

### Способ 2. Использование Jupyter Lab со встроенным `toc`

Jupyter Lab должен установиться вместе с окружением `practicum`, поэтому дополнительной установки не требуется.

### Старые проекты в новом окружении

Проекты с прежним оформлением могут некорректно отображаться после установки `toc2`:

- автоматическая нумерация наложится на номера в заголовках,
- ссылки в содержании перестанут работать.

Первой проблемой можно пренебречь: она затронет читателей проекта, только если у них установлено такое же расширение.

Содержание лучше исправить перед публикацией портфолио. Добавьте автоматическое содержание с помощью `toc2`. Такое содержание будет работать на любых компьютерах: с `toc2` и без.

## 2.Как называть учебные (и не только) файлы

1. **Не используйте кириллицу** — файлы принято называть латиницей.
2. **Не используйте пробелы** — вместо них пишите «-» или «_».
3. **Не начинайте с цифры** — это устаревший подход.
4. **Не используйте точку** — она должна отделять расширение файла от остального названия. Есть специальные файлы, названия которых начинают с точки, но это исключения.
5. **Не используйте заглавные буквы** — строчные смотрятся привычнее. Допустимо написание в стиле camel case: например, `myFileName`, но оно больше распространено среди специалистов по Java Script. Исключение: файлы `README`.
6. **Не используйте специальные символы** — @#$% и другие.

Старайтесь называть файлы оригинально. Например, начните с вашей фамилии: `фамилия_vN_89798789`. Например: `demidov_v1_876768`.

**Переименовывать файлы с проектами нельзя!**

### Новые горячие клавиши

Другое обновление — возможность настраивать горячие клавиши.

Горячие клавиши ускоряют работу. Самые полезные из них:

- `m` — из ячейки с кодом делает текстовую;
- `y` — из текстовой ячейки делает ячейку с кодом;
- `b` — добавляет новую ячейку под выбранной;
- `a` — добавляет новую ячейку над выбранной.

Иногда приходится работать на разных компьютерах, с Windows и macOS. В разных операционных системах — разные горячие клавиши. С помощью настроек их можно сделать одинаковыми.

Например, настроим запуск кода в ячейке на macOS по `Ctrl` + `Enter` — как на Windows:

1. Нажмите в меню Help → Edit Keyboard Shortcuts.
2. В списке команд найдите run cell.
3. В поле add shortcut впишите сочетание клавиш: `Ctrl-Enter`.

Теперь запустить код на macOS можно тем же сочетанием клавиш, что на Windows.

Поищите в списке команд те, которые часто вызываете через меню. Если добавить им сочетания клавиш, работать станет проще.

### Зачем выкладывать проекты в репозитории?

Прежде чем предложить вам место в компании, работодатель проверит ваш уровень владения нужными навыками. Например, через тестовое задание. Как правило, оно содержит пример реальной ситуации, с которой сталкивались или могут встретиться аналитики в компании. Часто тестовое не покрывает все возможные рабочие ситуации, поэтому работодатели изучают **проекты кандидата**.

Проекты, выполненные вами при прохождении курсов профессий Яндекс Практикум, дают представление о ваших знаниях и умениях и их соответствии требованиям работодателя.

Прикладывать к резюме выполненные проекты необязательно. Но их наличие — большой плюс.

### Каким правилам следовать при размещении проектов?

**1. Храните ваши проекты в репозиториях.**

Мы рекомендуем размещать свои решения в облачных репозиториях. **Репозиторий** — место, где хранятся и поддерживаются данные; чаще всего в виде файлов, доступных для дальнейшего распространения по сети. Популярные репозитории: Github, Gitlab, Bitbucket. Преимущество облачного репозитория — контроль доступа к нему. Вы можете сделать репозиторий как открытым для всех, так и закрытым. В закрытом репозитории ваши проекты будут доступны не всему Интернету, а только тем, кому вы выдаёте доступ.

Чтобы работать в этих сервисах, понадобятся знания основ **Git** — распределённой системы управления версиями. Её применяют для хранения нескольких версий одного и того же документа, с возможностью возвращения к ранним версиям и определения того, кто и когда вносил изменения.

**2. Не размещайте материалы курсов (тексты теории, задачи, квизы, датасеты) в репозиториях.**

Содержание курсов — плод трудов многочисленного авторского коллектива, редакции и консультантов из ведущих компаний России. Многие данные были эксклюзивно предоставлены команде «Яндекс Практикум» для обучения будущих специалистов.

**3. В своих проектах оставьте только то, что вы сделали сами.**

Основная цель репозитория — показать, на что вы способны. **Не размещайте в репозиториях полное описание проектов и предоставляемые наборы данных.** Как работодатель поймёт, о чём идет речь в проекте? Сделайте краткое описание к каждому проекту. Укажите источник данных и основные цели исследования. **Не забывайте удалять комментарии от ревьюера.** Они нужны для образовательных целей, работодателю эти комментарии ни к чему. Оставьте результаты обработки данных в результате исполнения ячеек: вызовы методов _info_, _head_ и других подобных, построение графиков и диаграмм — это всё показывает те навыки, которые вы приобрели в рамках обучения в Яндекс Практикуме.

**4. Размещайте проекты с описаниями в отдельных папках. Назовите папки так, чтобы можно было отличить один проект от другого. Не забывайте давать тетрадкам Jupyter Notebook значащие имена.**

Если вы назовёте свои проекты `super-duper-cool-project.ipynb`, `yet-anoter-super-duper-cool-project.ipynb`, `my-awesome-super-duper-cool-project.ipynb`, работодатель может запутаться в названиях и не понять, что вы делали в проекте.

Напомним, чтобы скачать тетради _Jupyter Notebook_ из тренажёра, перейдите на страницу проекта в меню _File_, выберите пункт _Download as_ и выберите формат _notebook_.

Зарегистрируйтесь на [github.com](http://github.com/). Чтобы создать свой репозиторий, войдите на Github, в правом верхнем углу нажмите на знак `+` и выберите пункт меню `New repository`.

![image](https://pictures.s3.yandex.net/resources/Untitled_1647956900.png)

Выберите имя репозитория — оно должно содержать строчные латинские буквы, цифры и тире. В поле `Description` можете внести краткое описание. Вы можете выбрать два варианта типа доступа для репозитория: публичный (public) и приватный (private). Если вы выберете приватный доступ, то репозиторий смогут просматривать только те, кому вы выдадите доступ. Дополнительно вы можете поставить галочку в пункте `Добавить в репозиторий файл README при инициализации`. Так, при создании репозитория markdown-файл readme будет доступен .

![image](https://pictures.s3.yandex.net/resources/Untitled_1_1647956903.png)

Чтобы посторонний человек — специалист по подбору персонала или ваш друг — мог посмотреть ваш репозиторий, нужно выдать доступ. Перейдите в меню `Settings → Collaborators` и в поле `Search by username, full name or email address` введите логин или email пользователя, которому хотите выдать доступ. Нажмите на `Add collaborator`:

![image](https://pictures.s3.yandex.net/resources/Untitled_2_1647956906.png)

После создания репозитория на github нужно продолжить работу с ним локально. Например, через клиентов с графическим интерфейсом: GitHub Desktop, SourceTree, GitKraken. Однако настоящие аналитики и специалисты по Data Science работают только с консольным интерфейсом. В освоении консольного git вам поможет интерактивный тур [https://githowto.com/ru](https://githowto.com/ru). Если вы затрудняетесь работать с консольным интерфейсом, рекомендуем скачать [GitHub Desktop](https://desktop.github.com/) и работать там. ### Как выложить мой проект?

#### Какая структура должна быть в репозитории?

- Для каждого проекта создайте отдельную папку.
- В папке должно содержаться два элемента: файл `README.md` и файл с расширением `.ipynb` c вашим решением проекта.
- Файл `README.md` должен содержать краткое описание проекта. Включите в описание рассказ об исследуемом наборе данных, основных пунктах и целях исследования; укажите библиотеки, которые вы использовали для выполнения проекта.
- Файл с расширением `.ipynb` должен содержать тетрадь с вашим выполненным проектом. Все ячейки в тетради должны быть выполнены, выводы ячеек (при наличии) должны быть сохранены.
- Файл с проектом не должен содержать комментариев наставника.
- В корне репозитория обязательно должен быть файл `README.md`. В этом файле должна быть структура репозитория: проекты, их краткое описание, что в какой папке находится.

### Часто задаваемые вопросы

- Стоит ли выкладывать переделанные проекты на Github? Как это сделать?

Если вы понимаете, что сделали проект не самым лучшим образом и что он показывает ваши знания и навыки не в лучшем свете, то стоит заменить его новым. Если же вы понимаете, что что-то нужно сделать по-другому, то можете в той же папке разместить новый проект с указанием в `README.md`, что изменилось.

- Стоит ли выкладывать решённые тестовые задания? Какие правила?

Вы можете выкладывать решённые тестовые, но при этом работают те же правила: выкладывать нужно только то, что относится к вашему труду. Не стоит указывать, какая компания выдала вам тестовое задание, а также полностью копировать описание задания в `README.md`.

- Стоит ли выкладывать свои решения с соревнований по Data Science?

Вы можете выкладывать свои решения с соревнований, но перед этим прочитайте правила: возможно, они запрещают публикацию решений. Однозначно не рекомендуем выкладывать решения текущих соревнований. Не забывайте в описании оставлять ссылку на соревнование.

## 4.Работа с локальным репозиторием с помощью консольного Git

### 1. Установка Git

В разных операционных системах Git устанавливают по-разному:

- в Linux — через командную строку. Перейдите по ссылке [https://git-scm.com/download/linux](https://git-scm.com/download/linux), найдите команду для вашей версии Linux.
- в Windows и macOS скачайте установочный файл с официального сайта [https://git-scm.com/](https://git-scm.com/).

Если программа-установщик предложит варианты применения Git, выбирайте «Использовать Git из командной строки» (_Use Git from... the Command Prompt_): задействовать все команды Git можно только из командной строки.

В Windows вместе с Git вам предложат установить Git Bash. Это специальная утилита, которая позволит вам использовать Bash под Windows, и все команды будут как на macOS. Мы предлагаем работать именно в нём.

### 2. Стартовая настройка Git

Откройте терминал для macOS или Git Bash для Windows. Чтобы убедиться, что Git установлен, запросите информацию о программе:

```
git --version 
```

Вы увидите сообщение:

```
git version 2.17.1 # это пример; может быть иная версия Git 
```

Следующим шагом укажите информацию о себе. Чтобы другие разработчики понимали, кто изменяет код, нужно сообщить программе Git ваши данные: имя пользователя и электронный адрес. Их мы пропишем в файле `.gitconfig` — в нём хранятся глобальные настройки программы. Для этого в командной строке запустите утилиту _git config_ с опцией `--global` (англ. _global_, «глобальные»). Свои данные укажите как значения свойств `user.name` и `user.email`:

```
git config --global user.name "Analitik Datascientistov" 
# вводите своё имя или ник латиницей и в кавычках 
```

```
git config --global user.email analitikds@yandex.com
# здесь нужно ввести свой реальный e-mail 
```

Проверьте, что получилось: выполните команду `git config` с опцией `--list` (англ. _list_, «список»):

```
git config --list
# вывели в окно командной строки список всех свойств конфига 
```

В открывшемся перечне (Windows) или новом файле (macOS) среди прочих свойств вы увидите свои данные:

```
user.name=Analitik Datascientistov
user.email=analitikds@yandex.com 
```

Выход из режима просмотра файла осуществляется нажатием клавиши `Q` (сработает при включённой латинской раскладке).

### 3. Создание, отображение, добавление

Организуем для нашего проекта рабочую директорию — папку с именем _yandex-praktikum-projects_.

Лишь папки недостаточно, нужно ещё сообщить программе Git, что файлы в этой папке нужно отслеживать. Этот процесс называется инициализацией и запускается командой _git init._

Инициализируем Git вызовом **git init** (от англ. _initialization_, «инициализация»).

```
# Сначала создаём папку для проекта, назовём её *yandex-praktikum-projects*.

mkdir *yandex-praktikum-projects*
# создали папку *yandex-praktikum-projects* в текущей директории

cd *yandex-praktikum-projects*
# перешли в созданную папку *yandex-praktikum-projects*

git init
# инициализировали git в папке *yandex-praktikum-projects* 
```

Команда _git init_ создаёт в папке с проектом скрытую поддиректорию **.git,** где хранится вся информация об изменении файлов.

### 4. Создание локального репозитория Git

Версионный контроль в Git предполагает, что любой файл репозитория находится в одном из четырёх состояний:

1. **неотслеживаемый** (англ. _untracked_),
2. **добавленный** в индекс, индексируемый (англ. _staged_, «выдвинутый на плацдарм»),
3. **изменённый** (англ. _modified_),
4. **боевой**, на жаргоне разработчиков «коммит» или «закоммиченный» (англ. _committed_, «брошенный в бой»).

Логика работы такая: как только в инициализированной папке появляется файл, он попадает в состояние неотслеживаемый. Что бы вы ни делали с этим файлом, Git будет игнорировать изменения.

Чтобы Git обратил внимание на этот файл и стал учитывать вносимые в него изменения, файл нужно добавить в индекс. После этого файл перейдёт в состояние «добавленный», а если после этого внести в него изменения — в состояние «изменённый».

Когда мы закончим изменение файла, нам нужно его «сохранить» — сообщить программе Git, что актуальное состояние файла нужно запомнить. Позже это позволит нам вернуться к этой версии, если что-то пойдёт не так.

Такое сохранение называют **коммитом**:

![image](https://pictures.s3.yandex.net/resources/Untitled_4_1647958066.png)

Команды Git, которые нам предстоит изучить, выполняют одну из трёх задач:

- изменяют состояние файла;
- отображают информацию о файле;
- показывают разницу между его версиями.

### 5. Команды Git

#### 5.1. **git add**

**git add** (англ. _add_, «добавить») — команда для добавления файлов в индекс **Staging Area** (англ. «плацдарм», «место временного сосредоточения», «временное хранилище»). После этой команды нужно указать имя файла, судьбу которого поручено отслеживать: `git add название_файла`.

Можно добавить все файлы сразу прибегнув к опции **-- all** (англ. all, «все»). Файлы из вложенных каталогов так же добавятся в индекс:

`git add --all`

Опцию **-- all** можно заменить точкой: `git add .`

```
git add project1.ipynb
# добавили файл project1.ipynb

git add --all
# добавили все файлы

git add . 
# добавили все файлы 
```

#### 5.2. **git commit**

Чтобы сохранить состояние файлов нужно сделать коммит — зафиксировать все сделанные изменения в «боевой версии» и оставить комментарий. Делают это специальной командой **git commit** (англ. _commit_, «бросить в бой») c ключом **-m** (от англ. _message_, «послание»). После этого ключа требуется комментарий в кавычках:

```
git commit -m "My first commit"
# сделали первый коммит
# текст комментария - "My first commit", в переводе "мой первый коммит"
# комментарии лучше писать латинским алфавитом, чтобы они корректно отображались в командной строке 
```

Пишите комментарии так, чтобы потом вам было легко разобраться, какие изменения были сделаны в каждом коммите.

#### 5.3. **git clone**

Самое время опубликовать проект! Скопируйте репозиторий из облака на локальное хранилище командой **git clone** (англ. _clone_, «клонировать»):

```
git clone [адрес, откуда копируем] [путь до папки, куда копируем] 
```

Откройте командную строку и клонируйте репозиторий в память своего компьютера. Не забывайте: если вы уже находитесь в той папке, куда нужно клонировать, путь указывать не надо. Достаточно указать ссылку на клонируемый проект:

```
git clone https://github.com/<user>/<repository>.git
# скопировали репозиторий с сайта github в текущую директорию 
```

После клонирования на компьютере появится папка с названием репозитория. Зайдём в неё из командной строки:

```
cd <repository>.git
# перешли в папку с проектом 
```

Скопируйте все файлы c проектами в этот репозиторий. Добавьте все файлы:

```
git add --all
# добавили всё 
```

Сделайте коммит:

```
git commit -m "First commit"
# сделали коммит с комментарием First commit 
```

#### 5.4. **git push**

Вот и настал момент загрузки вашего сайта на удалённый репозиторий. Для этого есть команда **git push** (англ. _push_, в значении «от себя»). Так как мы скопировали готовый репозиторий с сервера, для первой публикации изменений вызовем команду _git push_ с ключом _-u_ и двумя аргументами:

- первый аргумент — имя сервера, с которого вы скопировали репозиторий: **origin** (англ. «источник»);
- второй аргумент — имя ветки: **master**;
- ключ **-u** связывает локальную ветку с веткой удалённого репозитория. Этот ключ нужен, только если вы публикуете новые ветки.

Опубликуем новую ветку:

```
git push -u origin master 
```

Если всё прошло хорошо, вы увидите добавленные файлы в своём репозитории на сайте GitHub.

Если вы храните свои репозитории на разных компьютерах, то когда вы публикуете сделанные на одном компьютере изменения, на другом — их нужно получить командой _git pull_.

#### 5.5. **git pull**

Команда **git pull** (англ. _pull_, в значении «на себя») заносит все созданные коммиты в вашу рабочую ветку. Выполнение этой команды может привести к конфликтам, так как все изменения при получении сразу сливаются с вашей веткой.

```
git pull 
```

### 6. Хранение файлов с помощью .gitignore

При работе с локальным репозиторием иногда хочется положить в папку с репозиторием дополнительные документы или даже папки, но так, чтобы они не попали в удалённый репозиторий на Github. Для этого нужно создать файл `.gitignore`. Это простой текстовый документ, в каждой строчке которого написана маска файлов, которые не должны попасть на удалённый репозиторий после команды _git pull_.

Ниже есть примеры шаблонов в строках файла `.gitignore`

```
# комментарий — эта строка игнорируется

# игнорировать файлы с расширением .pyc, 
# * - любое количество символов (ноль и больше), 
*.pyc
# НО отслеживать файл main.pyc
# несмотря на то, что мы игнорируем все .pyc файлы с помощью предыдущего правила
!main.pyc
# ? - ноль или один символ
# Исключить файлы text.txt, test.txt, tet.txt и т.д. 
te?t.txt
# игнорировать только файл main.py находящийся в корневом каталоге
# не относится к файлам вида <папка>/main.py
/main.py
# игнорировать все файлы в каталоге .idea/
.idea/
# игнорировать файлы с расширением .txt, только в папке doc, но не в подпапках папки doc
doc/*.txt
# игнорировать все .txt файлы в каталоге doc/ и всех его подкаталогах
doc/**/*.txt 
```

Если вы добавили файл в репозиторий и опубликовали изменения командой _git pull_, но не добавили шаблон для файла в `.gitignore`, то он будет опубликован на Github. После добавления шаблона в `.gitignore`, изменения в файле не будут отражаться на Github, но сам файл не будет удалён с репозитория.

Чтобы удалить файл, удалите его, зафиксируйте и опубликуйте изменения. Затем добавьте файл и добавьте его шаблон в `.gitignore`. После этого снова опубликуйте изменения.
