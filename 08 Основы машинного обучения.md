# Наука о данных
## Жизненный цикл данных
В предыдущих уроках вы учились анализировать данные с помощью Python: проводить статистические исследования, искать причины и следствия. Это довольно объёмный и сложный этап в работе с данными, но всё же это лишь один из этапов.

Перед анализом данных нужно каким-то образом их собрать и каким-то образом хранить. И сам анализ не всегда оказывается конечным этапом, его результаты могут стать поводом для создания регулярной отчётности с помощью дашборда или построения моделей машинного обучения, которые помогают бизнесу принимать решения.

Данным нужно пройти цикл работ для того, чтобы они принесли пользу.

### В этом уроке вы узнаете

- что такое жизненный цикл данных;
- через какие этапы проходят данные;
- какие специалисты отвечают за каждый из этапов.

### Жизненный цикл данных

Данные «живут», пока они нужны и пока с ними работают. Они проходят через множество этапов — назовём их жизненным циклом. Через какие же этапы проходят данные?

![](https://pictures.s3.yandex.net/resources/8.8.1.1_1_1715452419.png)

#### **Сбор данных (Интеграция)**

Для начала данные нужно откуда-то собрать. На этом этапе решают такие вопросы:

1. Из какой системы собирать данные? Это называют источником данных.
2. Каким способом собирать данные? Это может быть какой-то сервис, скрипт или что-то другое.
3. Как часто собирать данные? Данные можно получать раз в день, раз в час, а можно получать их непрерывно в реальном времени.

Это могут быть данные с сайтов, собираемые с помощью Яндекс Метрики или Google Analytics (GA). Эти инструменты помогают собирать данные о действиях пользователей сайта. Ещё их называют трекерами — иногда компании создают собственные трекеры, но их задача примерно одинаковая.

Ещё одним источником данных могут быть внутренние сервисы, например CRM (Customer Relationship Management — Система контроля взаимодействия компании с клиентами) или ERP (Enterprise Resource Planning — Система управления внутренними бизнес-процессами компании, например данные по логистическим операциям или учёт персонала) системы.

Источником данных становятся не только внутренние, но и внешние системы. Они не принадлежат напрямую компании. В таком случае для сбора данных используют API (Application Programming Interface — Интерфейс взаимодействия с системой). О том, как работать с API, вы узнаете в следующем модуле.

Этап проектирования сбора данных называют интеграцией. Интеграция — очень важный и многосоставной процесс. Обычно ею занимаются совместно несколько специалистов:

- **разработчик (DevOps / Backend / Frontend / Fullstack)** — он лучше знает, как устроена система-источник данных. Разработчики бывают разные: DevOps-инженер разбирается в инфраструктуре вокруг системы, Backend-разработчик много знает о самой системе, а Frontend-разработчик понимает, как система взаимодействует с пользователем. Какой человек нужен — зависит от задачи. Иногда эти роли совмещает один разработчик, которого называют Fullstack, но так бывает не всегда.
- **инженер данных (Data Engineer)** — он лучше знает, как именно собирать данные и что нужно для этого сделать.
- **аналитик данных (Data Analyst)** — он лучше знает, какие именно данные необходимы. На этом этапе аналитик помогает инженеру лучше понять задачу.

#### **Хранение данных**

Если мы собрали данные, то нужно определиться, как правильно их хранить. На этом этапе выбирается подходящее хранилище данных.

Все хранилища можно разделить на 2 вида: холодные и горячие.

**Холодное** хранилище предназначено для хранения огромного количества сырых данных. Сырые — это те данные, которые только собрали, но они ещё не готовы к анализу. Их часто помечают как _raw_ (от англ. сырой). Хранилищем может быть S3 или HDFS (Hadoop File System), а может быть и просто обычное облачное пространство, по типу Google Drive или Яндекс Диск. Такое хранение ещё не подходит для анализа, но становится промежуточной точкой, из которой данные попадут в горячее хранилище.

**Горячее** хранилище уже предназначено для анализа данных. Обычно это базы, созданные с использованием SQL-технологий. Примеры, которые встречаются чаще всего: Postgres, Clickhouse, Vertica и Greenplum. В горячие хранилища попадают данные с уже понятной структурой и готовые к анализу. С помощью Python вы можете выгружать эти данные и сохранять нужные срезы в виде CSV или других файлов, с которыми вы уже работали в прошлых уроках.

За то, как именно хранить данные, отвечает **инженер данных**.

#### **Подготовка данных**

На этом этапе данные уже где-то хранятся, но ещё не факт, что готовы к анализу. Пора приступать к этапу предобработки.

Данные приводятся к нужным структурам. Если нужно, то их агрегируют или фильтруют. Затем проверяют качество данных (Data Quality) — ищут несоответствия, ошибки, пропуски и дубликаты.

Результатом предобработки становятся готовые срезы с данными для аналитиков. Ещё их называют витринами данных (Data Mart).

За этап подготовки данных отвечают **инженер данных** и **аналитик данных**. Иногда процесс оценки и улучшения качества данных выделяют в отдельный этап и выделяет на него **Data Quality** специалиста.

#### **Анализ данных**

После сбора данных пора приступать непосредственно к анализу. На этом этапе наша задача — показать ценность данных, с помощью них ответить на все возникающие вопросы. Исследовать закономерности, тренды и другие аналитические штуки, с которыми вы ознакомились на прошлых уроках.

Результаты исследований напрямую влияют на все дальнейшие этапы.

Этап анализа целиком ложится на ответственность **аналитика данных**.

#### **Регулярная отчётность**

Обычно потребность в регулярных отчётах появляется сразу после первичного анализа.

Регулярная отчётность позволяет отвечать на актуальные вопросы в любое время дня. Например, сколько заходов на сайт было вчера, какое количество заказов отгружено за последний месяц или как быстро открывается сайт прямо сейчас.

Чтобы аналитику не отвечать на одни и те же вопросы каждый день, создают дашборды с графиками, которые постоянно обновляются. В итоге для ответа на ряд вопросов достаточно лишь посмотреть на дашборд.

Для создания дашбордов используют BI (Business Intelligence) системы. Например, PowerBI, Tableau, Metabase, Superset, Datalens, Grafana и другие.

Эту задачу решает **аналитик данных** или **инженер данных**. Но иногда под эти задачи выделяют отдельную роль — **BI Analyst**.

#### **Моделирование данных**

Результаты исследований используют при создании ML (Machine Learning — машинное обучение) моделей. ML-специалисты проводят собственные исследования и помогают отвечать на вопросы бизнеса. Они могут сделать следующие вещи:

- составить прогноз спроса, чтобы запланировать траты на предложение;
- оценить вероятность просрочки по кредиту с помощью скоринговой модели.

Моделирование требует хороших знаний математики. Как правило, этой задачей занимается **дата-сайентист**, но иногда эту работу может выполнять и **аналитик данных**.

На основе успешных моделей создают целые сервисы, которые работают уже автономно. Они помогают принимать решения уже без участия ML-специалиста, к примеру:

- составлять оптимальный маршрут перевозки для водителей;
- блокировать заходы на сайт от ненастоящих пользователей (ботов), вычисляя их на основе множества параметров;
- планировать выход персонала на основе данных о загруженности предприятия.

За создание таких сервисов отвечает **ML Engineer**, он хорошо разбирается и в математике, и в разработке.

### Какие специалисты участвуют в жизненном цикле данных

В небольших командах случается так, что за все этапы в жизненном цикле данных отвечает один человек. Иногда это действительно имеет смысл, но в большинстве случаев эти роли разделяют на основе компетенций. Как правило, их три — разработка, математика и знания предметной области.

Знания предметной области — это понимание бизнес-процессов, в рамках которых необходимо провести анализ. Например, аналитику данных необходимо хорошо разбираться в предметной области, а ML-специалист больше фокусируется на математике.

### Итоги

В процессе жизненного цикла данные проходят через несколько этапов. Вот основные:

- сбор данных: определение источников данных, способов и частоты сбора;
- хранение данных: выбор подходящего способа хранения данных;
- подготовка данных: очистка, преобразование и агрегация данных;
- анализ данных: исследование закономерностей, трендов и ответы на бизнес-вопросы;
- регулярная отчётность: создание дашбордов и визуализаций для постоянного мониторинга;
- моделирование данных: построение аналитических моделей, в том числе с использованием машинного обучения.

За каждый этап жизненного цикла данных отвечают разные специалисты с определённым уровнем компетенций:

- data analyst (аналитик данных) — отвечает за анализ данных и создание регулярной отчётности. Этот человек отлично погружён в предметную область.
- data engineer (инженер данных) — отвечает за хранение и подготовку данных. Больше разработчик, чем аналитик.
- data scientist (дата-сайентист или специалист по машинному обучению) — отвечает за моделирование данных. Больше математик, чем аналитик.

В этом уроке вы ознакомились с новым этапом в работе с данными — моделированием. В следующем уроке вы ещё глубже погрузитесь в эту тему и узнаете, как учатся машины и что такое ML-модель.

## Способы машинного обучения
В прошлом уроке вы ознакомились с жизненным циклом данных и узнали, что этап анализа не всегда оказывается последним. Следующим этапом может стать моделирование данных и построение ML-моделей.

В этом уроке вы узнаете:

- что такое машинное обучение и ML-модель;
- как обучаются модели;
- какие задачи решают с помощью методов машинного обучения.

### Что такое машинное обучение

Машинное обучение, или Machine Learning (ML), — это наука, в которой задачи решаются с помощью обучения на основе данных. Обычно такие задачи заключаются в поиске связей и закономерностей. Как правило, этим занимается сам человек, но когда этим занимается компьютер, то это называют машинным обучением.

Представьте, что вы хотите научить робота продавать лимонад. Вам нужно заранее подготовить ингредиенты для лимонада, но если неправильно оценить спрос, то лимонада может не хватить или его останется слишком много. Сначала робот учится — он смотрит на то, сколько лимонада вы продаёте каждый день. Он может заметить, что, когда на улице тепло, вы продаёте больше лимонада, а когда холодно — меньше. Или что по выходным продажи всегда растут. Никто не говорит об этом напрямую роботу, он находит эти закономерности сам, просто обучаясь на данных.

После обучения вы даёте возможность роботу самостоятельно продавать лимонад так, чтобы он планировал объёмы, и следите за тем, насколько часто он ошибается. Если робот редко ошибается, то можно передать дело ему и спокойно отдыхать. Но если робот ошибается часто, то нужно поменять алгоритм обучения и попробовать заново.

Примерно так и работает машинное обучение.

С помощью машинного обучения решают такие задачи:

- прогнозирование сезонного спроса на товары;
- скоринговая модель для оценки платёжеспособности клиентов банка;
- обнаружение мошеннических схем на основе банковских транзакций;
- создание персональных рекомендаций на маркетплейсе;
- распознавание лица по фотографии.

### Что такое ML-модель

ML-модель — это программа, которая обучается на данных и решает задачи, используя методы машинного обучения. Любая готовая к работе ML-модель работает так: на вход ей передаются данные, на выход она отдаёт какой-то результат.

![](https://pictures.s3.yandex.net/resources/1_1715344462.png)

В большинстве случаев мы точно знаем, как устроена ML-модель и какие алгоритмы она использует, но так бывает не всегда. Иногда логика работы ML-модели может быть очень запутанной или даже скрытой. Такую модель называют «чёрным ящиком», когда пользователь не знает, как именно работает модель, но знает, какую задачу она помогает решать. Один из примеров таких чёрных ящиков — ChatGPT или другие популярные языковые модели. Мы не знаем точно, как они работают, но они работают.

### Как обучаются модели

Обучение с учителем заключается в том, что вначале алгоритм учится находить закономерности в данных на основе правильных ответов. У алгоритма будто есть учитель, который знает, как «правильно», и алгоритм учится работать так же, как в нашем примере с лимонадом.

Данные с уже указанными правильными ответами называют размеченными. Разметка данных — ручной процесс, как правило, человек сам занимается разметкой, к этому этапу необходимо подходить с особой внимательностью, это напрямую влияет на работу модели.

Вот несколько примеров задач, которые решаются с помощью обучения с учителем:

- Распознавание изображений: такие модели могут анализировать изображения и определять объекты, которые они содержат. Например, распознавать ваше лицо при входе в систему, основываясь на ваших фотографиях в прошлом.
- Обнаружение мошенничества: эти алгоритмы помогают выявлять подозрительные транзакции, которые могут быть мошенническими, на основе анализа данных о мошеннических операциях в прошлом.
- Прогнозирование спроса: модели помогают компаниям лучше планировать производство и поставки на основе данных о поставках в прошлом. Это называют задачей регрессии.

Распространённая проблема такого подхода — переобучение. Это когда алгоритм настолько натренировался на входных данных, что он отлично и без ошибок с ними справляется, но очень плохо работает на новых данных, которые ещё не видел. Это как учиться водить машину только по одной улице: вы отлично научились по ней передвигаться и знаете каждый светофор, но на других маршрутах вы теряетесь. В следующих уроках вы узнаете о способах борьбы с переобучением.

#### **Обучение без учителя**

В этом случае у алгоритма нет информации о том, какие результаты правильные, а какие нет. То есть нет учителя, который подскажет, какой результат должен быть. А значит, тяжело проверить, насколько модель хорошо справляется со своей задачей.

С помощью обучения без учителя можно решать следующие задачи:

- Кластеризация данных: такие модели помогают группировать или сегментировать похожие данные вместе. Например, найти фильмы, похожие на ваш любимый.
- Снижение размерности данных: когда у данных много признаков (например, огромное количество технических характеристик для компьютеров), такие модели могут помочь снизить число этих признаков и оставить только самые важные, имеющие значение для анализа.
- Ассоциативный анализ: такие задачи помогают находить взаимосвязи и зависимости в данных.

#### **Другие способы**

Есть и другие способы обучения. Они решают другие, более специфические задачи, пройдёмся кратко по каждому:

**Обучение с подкреплением** — такой метод работает на основе обратной связи при обучении. Модель пытается учиться и решает задачу каждый раз по-разному. Если получается хорошо, то мы даём позитивную обратную связь, так модель учится находить более оптимальные решения. Этот подход полезен, когда мы заранее не знаем правильных решений задачи, однако он более сложен, так как требует создания какой-то среды, в которой модель учится. Беспилотные автомобили учат водить именно таким образом.

**Обучение с частичным участием учителя** — модель учится на размеченных и неразмеченных данных сразу. Обучаясь на размеченных данных, модель пытается разметить то, что осталось, и дообучиться на новых данных. Такой способ помогает, когда данных для разметки становится слишком много или сама разметка занимает много ресурсов.

**Глубинное обучение (Deep Learning)** — основное отличие от классических принципов в использовании нейронных сетей при обучении. При этом само обучение обычно строится на размеченных данных. Такой класс задач помогает находить сложные закономерности в данных (например, распознавать образы).

### Итоги

- Машинное обучение (ML) — это наука, в которой задачи решаются с помощью обучения на основе входных данных.
- ML-модель — это программа, которая решает задачи, используя методы машинного обучения.
- Существует два основных подхода в машинном обучении:
    - Обучение с учителем — модель обучается на размеченных данных с правильными ответами;
    - Обучение без учителя — модель сама находит закономерности в данных без заранее известных ответов.

## Машинное обучение в аналитике
В прошлом уроке вы ознакомились с основными способами обучения моделей: обучением с учителем и без учителя. Каждый способ помогает решать определённый класс задач, а вам важно уметь определять, к какому классу относится аналитическая задача.

Определить, есть ли котята на фотографии, и установить платёжеспособность клиента банка — как ни странно, это задачи одного класса, а именно задачи классификации. В первом случае мы классифицируем изображения с котятами и без них, а во втором — клиентов банка. Для понимания общих подходов решения задач классификации не так важно, что и как мы классифицируем.

Определение класса задачи — это первая проблема, с которой может столкнуться аналитик. Как же определить класс задачи и какие типы задач вообще бывают?

В этом уроке вы узнаете:

- какие задачи решают, используя обучение с учителем и без него;
- как понять, к какому классу относится аналитическая задача;
- чем кластеризация отличается от классификации;
- что такое ассоциативный анализ.

### Типы задач машинного обучения

#### **Обучение с учителем**

Напомним, что обучение с учителем — это когда модель сначала обучается на размеченных данных. То есть на тех данных, у которых уже указан верный результат работы. В случае определения котят на изображении у нас были бы сами изображения и значение — есть на них котёнок или его нет.

**Задача классификации**

Эти задачи помогают определить, к какой группе или _классу_ относится объект. Такие задачи решаются с учителем, то есть на основе разметки. Вы уже ознакомились с примерами таких задач, пройдёмся подробнее:

1. Определить платёжеспособность клиента банка, чтобы оформить кредит. Модель обучается на исторических данных о выданных кредитах и фактах просрочек, используя все доступные характеристики клиента — возраст, пол, образование и другие данные.
2. Распознать объекты на изображении. Модель обучается на размеченных изображениях. Обычно при этом используются нейронные сети, которых мы касаться не будем.
3. Диагностировать заболевания на основе медицинских анализов. На данных о бывших пациентах и их диагнозах модель обучается классифицировать результаты по известным заболеваниям.
4. Определить эмоции по речи человека. Модель обучается на размеченных аудиозаписях, где авторы указывали свои эмоции во время речи.

**Задачи регрессии**

За непривычным словом _регрессия_ скрывается довольно простой смысл. Задача регрессии сводится к тому, чтобы спрогнозировать значение одной величины на основе других переменных. Другими словами, она помогает определить зависимость между различными параметрами и выполнить подобные задачи:

- спрогнозировать стоимость жилья, используя данные о характеристиках дома (площадь, количество комнат, местоположение). Модель обучается на данных с уже проданными домами и их характеристиками из объявлений;
- спрогнозировать спрос на товары и услуги на основе данных о продажах, рекламе и сезонности. Модель обучается на исторических данных о продажах, учитывая указанные параметры;
- определить зарплату на основе данных о возрасте, образовании и опыте работы. Такая модель может спрогнозировать вероятную заработную плату сотрудника в текущих реалиях. Такая модель обучается на данных о сотрудниках, недавно нашедших работу.

Есть большой подкласс задач регрессии — прогнозирование временных рядов. Это набор значений, который меняется со временем. Например, метрика DAU, которая как-то меняется в течение последних пары месяцев. Это тоже задача регрессии, в таком случае мы можем представить, что время — это некоторая переменная, изменение которой влияет на основной показатель.

![](https://pictures.s3.yandex.net/resources/image_1715357759.png)

Если задача сводится к предсказаниям или прогнозированию, то, скорее всего, перед вами задача регрессии.

Итак, основные типы задач машинного обучения с учителем: классификация и регрессия.

![](https://pictures.s3.yandex.net/resources/image_1715357780.png)

#### **Обучение без учителя**

При обучении без учителя модель учится без разметки. Трудно представить, как научиться классифицировать или прогнозировать данные без разметки. С этим типом обучения решают другие задачи — сейчас расскажем, какие именно.

**Задачи кластеризации**

В таких задачах мы разбиваем данные на группы на основе сходства между объектами. Этими объектами могут быть изображения, аудиофайлы, клиенты интернет-магазина, пользователи социальной сети или что-то другое. Ещё эти группы называют кластерами.

В отличие от задач классификации, здесь мы не знаем заранее о том, какие группы данных существуют и даже сколько их. Модель узнает об этом только в процессе обучения. Здесь всё сводится к определению схожести в данных. В том, как определить эту «схожесть», и есть вся изюминка таких задач.

Примеры задач кластеризации:

- разделить клиентов компании на группы (кластеры) с похожими характеристиками (демография, поведение, предпочтения) для таргетированного маркетинга, это называют сегментацией клиентов;
- выделить выбросы в данных для обнаружения мошенничества, сбоев в работе оборудования или других нетипичных ситуаций, это называют обнаружением аномалий;
- выделить группы пользователей с похожими интересами, поведением или связями, с помощью такой задачи социальные сети развивают таргетированную рекламу и свои системы рекомендаций.

**Задачи снижения размерности**

Цель таких задач — уменьшить количество признаков в данных, сохранив при этом полезную информацию. Например, сравнивая клиентов, где каждого характеризует до 50 различных параметров (возраст, пол, образование, семейное положение и другое), мы можем снизить размерность и оставить, например, 2–3 главных. Это сильно упростит исследование.

Вот несколько примеров задач, где может помочь снижение размерности данных:

- визуализация данных: преобразование многомерных данных в двух- или трёхмерное пространство для визуализации и анализа. Как в примере с характеристиками клиентов, где мы перешли из 50-мерного в 2–3-мерное;
- сжатие изображений: модель выявляет и удаляет избыточную информацию на изображении, которая не влияет на восприятие человеком. Это помогает в экономии памяти и ускоряет процесс обработки без значительной потери качества изображения;
- улучшение работы рекомендательных систем: сокращение размерности данных о предпочтениях пользователей для более точного и персонализированного предложения товаров или услуг.

**Задачи ассоциативного анализа**

Цель таких задач — найти взаимосвязи и закономерности в данных. Это помогает находить скрытые шаблоны и зависимости в наборах данных.

Вот примеры задач, которые решают, используя ассоциативный анализ:

1. найти правила вида «если-то», «то-то», где определённые элементы данных ассоциируются друг с другом. Например, **если** в корзине покупок встречаются хлеб и молоко, **то** с высокой вероятностью там будут и яйца;
2. построить рекомендации для пользователей, предлагая им товары или услуги, которые могут заинтересовать их на основе предыдущих покупок или действий. **Если** пользователь смотрел фильмы «Интерстеллар» и «Довод», **то**, возможно, ему понравится другие фильмы Кристофера Нолана;
3. определить взаимосвязи в логистических процессах между маршрутами, видами транспорта, погодными условиями и другими факторами для повышения эффективности цепочек поставок.

Итак, основные типы задач машинного обучения без учителя: кластеризация, снижение размерности и ассоциативный анализ.

![](https://pictures.s3.yandex.net/resources/image_1715357818.png)

Определение класса задачи считается важным первым шагом для аналитика при решении задач с помощью машинного обучения. Каждый класс задач имеет свои особенности и требует применения соответствующих методов и алгоритмов.

- Основные типы задач машинного обучения **с учителем**:
    - задачи классификации — определение, к какому классу или группе относится объект;
    - задачи регрессии — прогнозирование значения целевой переменной на основе других признаков.
- Основные типы задач машинного обучения **без учителя**:
    - задачи кластеризации — разбиение данных на группы (кластеры) на основе сходства между объектами;
    - задачи снижения размерности — уменьшение количества признаков в данных, сохраняя при этом полезную информацию;
    - задачи ассоциативного анализа — поиск взаимосвязей и закономерностей в данных.

## От задачи к модели
Применение ML в анализе данных имеет огромные успехи. В больших компаниях всё чаще встречаются целые отделы и направления со специалистами, решающими задачи при помощи методов машинного обучения. Благодаря этому подходы и методы развиваются очень быстро.

Но всё же в машинном обучении мы сталкиваемся с ограничениями, с которыми приходится бороться и которые важно иметь в виду.

В этом уроке вы узнаете:

- какие шаги помогут подготовиться к обучению модели;
- как правильно обучить модель;
- как оценивают качество модели.

### Как подготовиться к обучению

Процесс обучения моделей требует от аналитика внимательности и аккуратности. К этой задаче необходимо подготовиться заранее.

#### **Постановка задачи**

В прошлом уроке вы узнали, как важно понимать тип задачи машинного обучения и определять, что перед вами задача регрессии, а не классификации. Это важный этап, но всё же не самый первый.

Машинное обучение начинается с постановки задачи. Именно благодаря хорошо сформулированной задаче мы принимаем решение о её типе и о том, какими способами будем пробовать решать.

Как хорошо формулировать задачу? В рамках темы исследовательских гипотез вы узнали, чем отличается плохая гипотеза от хорошей. Тут всё очень похоже.

Вот пример плохой постановки задачи:

❌ Создать модель, которая поможет нам увеличить продажи.

А вот пример правильной постановки задачи:

✅ Разработать модель машинного обучения для прогнозирования спроса на товары в интернет-магазине с точностью не менее 85%, чтобы оптимизировать запасы и улучшить обслуживание клиентов.

Правильная постановка задачи содержит:

- цель, к которой мы стремимся;
- измеримый критерий, по которому мы можем судить о том, как хорошо модель обучилась.

С правильной постановкой задачи у вас не должно оставаться вопросов вроде «Что мы улучшаем?» или «Как оцениваем качество?».

Сам аналитик редко бывает заказчиком такой задачи, обычно к нему приходят менеджеры или руководители. Аналитику важно задавать как можно больше уточняющих вопросов по задаче, не должно быть недопониманий.

### Исследовательский анализ

Исследовательский анализ (EDA) — обязательный этап перед тем, как начать обучать модель. Это объёмный этап, состоящий из нескольких шагов, с которыми вы уже знакомы:

1. **Анализ качества данных и их предобработка.** В процессе EDA мы обнаружим пропуски, дубликаты и аномалии, которые портят выборку. Важно готовить данные к обучению наиболее «чистыми», без аномалий и пропусков. При обучении нужно помнить о принципе garbage in — garbage out («мусор на входе — мусор на выходе»). Обучаясь на плохих данных, мы всегда получим плохой результат.
2. **Определение признаков.** Мы должны определить наиболее важные признаки, которые полезны для моделирования, чтобы не включать в модель ненужные или неинформативные признаки. Например, рост человека вряд ли повлияет на его годовой доход, а температура воздуха на просмотры рекламы. Определение признаков поможет избежать ложной корреляции и неверной интерпретации результатов.
3. **Проверка гипотез.** На этапе EDA мы можем проверить гипотезы, влияющие на то, какую модель машинного обучения будем использовать. Может оказаться, что модель и не нужна вовсе.

#### **Разметка данных**

Этот этап важен только для обучения с учителем, где модель учится на размеченных данных. Разметка может оказаться самым продолжительным этапом, так как требует внимательности, а данных для разметки нужно очень много. Ведь не получится научить модель хорошо распознавать котят на фотографии лишь по одному примеру. Модели может потребоваться десятки, сотни, а возможно, и тысячи таких фотографий. И все изображения должны быть размечены, причём верным способом. Помните, что garbage in — garbage out.

Есть сервисы, которые помогают в решении таких задач, один из популярных — [toloka.ai](http://toloka.ai/). Но такая помощь будет стоить денег, хоть и не всегда больших.

#### **Ещё больше данных**

Для обучения вам может понадобиться много данных. Их количество зависит от задачи и требуемой точности модели. Но если ваша табличка состоит из 10 строк, то, скорее всего, этого недостаточно. Чем больше данных вам доступно — тем лучше.

Обучение модели — очень сложный процесс с точки зрения вычислений для компьютера. Бывает, что на больших данных модель обучается часами или даже днями. Увеличивая количество данных, вы повышаете требования к техническим ресурсам своего компьютера.

### Как обучают модели

Итак, мы подготовили данные, на которых должна обучаться модель. Что же дальше?

Мы делим данные на две выборки: тренировочную и тестовую. На тренировочной модель обучается, а на тестовой мы оцениваем, с какой точностью модель справляется с работой.

У вас могут возникнуть вопросы: «Почему бы не тренировать модель на всех доступных данных?» и «Зачем нужны тестовые данные?». Ведь чем больше данных, тем лучше модель обучается. И это хорошие вопросы, на то есть причина — борьба с переобучением.

Переобучение — это когда алгоритм настолько натренировался на входных данных, что он отлично и без ошибок с ними справляется, но очень плохо работает на новых данных, которые ещё не видел. Это как учиться водить машину, но только по одной улице: вы отлично научились по ней передвигаться и знаете каждый светофор, однако на других маршрутах вы теряетесь.

Мы не можем слепо верить, что модель действительно хорошо работает, используя только учебные данные. Для проверки того, что модель действительно обучилась, а не просто «зазубрила» правильные ответы, необходимо дать ей те данные, которых она ещё не видела, — тестовые.

Данные, на которых модель обучается, называют тренировочными. А те данные, на которых оценивают точность модели, — тестовыми. Обычно их делят в соотношении 80 (тренировочные) / 20 (тестовые), но можно использовать и другие пропорции (например, 70/30 или даже 50/50).

![](https://pictures.s3.yandex.net/resources/8.8.1.4_2_1716315165.png)

Иногда отделяют ещё одну часть данных, их называют валидационными.

Валидационные данные используют для подбора самой модели и проверки того, что она работает корректно и не переобучилась. Их не используют для оценки качества работы модели, для этого мы используем тестовые данные. Если данных много, эти выборки делят в соотношении 80 (тренировочная) / 10 (валидационная) / 10 (тестовая), но можно использовать и другие пропорции (например, 70-20-10).

![](https://pictures.s3.yandex.net/resources/8.8.1.4_1_1716315173.png)

Не стоит переживать, что мы даём модели меньше данных для тренировки. Валидация и тестирование нужны для улучшения её качества. Переобучение может поджидать вас там, где вы не ждали, и испортить точность вашей модели.

###### Как понять, что модель работает хорошо

Для того чтобы оценить качество или точность работы модели, используют тестовые данные. Но процесс оценки всегда зависит от самой задачи, нет единого правила для оценки качества всех моделей.

Самый простой способ оценить точность модели — посмотреть на результаты работы ML-модели и сравнить её с верными ответами или разметкой. То, как часто модель ошиблась, и будет относительной ошибкой. Есть и другие способы оценки (например, R-квадрат для задач регрессии или F1-мера для задач классификации). С этими и другими критериями вы ознакомитесь в следующих уроках.

Проверка качества модели зависит от задачи, которую вы решаете, особенно это справедливо для задач без учителя, где нет разметки, а значит, что вы не можете в явном виде сравнить то, как часто модель ошибается на тестовых данных.

### Итоги

- Важно чётко сформулировать цель и критерии успеха для модели машинного обучения. Хорошая постановка задачи содержит цель и измеримый критерий успеха.
- Нельзя подходить к моделированию данных без предварительной аналитики и обработки данных. Исследовательский анализ — обязательный этап перед началом обучения. Garbage in — garbage out.
- При обучении используют только часть доступных данных — это тренировочная выборка. На оставшихся данных проверят работоспособность модели — это тестовая и валидационная выборки.
- Способ оценки качества модели зависит от типа задачи, и нет универсального инструмента.

## Масштабирование данных
Количественные переменные в реальных данных часто отличаются друг от друга: у них разные средние, стандартное отклонение и другие свойства. Чтобы это исправить, нужно привести их к одному масштабу, — то есть масштабировать.

В этом уроке вы узнаете, какими способами это можно сделать и как реализовать это в Python.

Масштабирование делают не из стремления к красоте и единообразию. Оно устраняет возможные дополнительные неточности модели при обучении на неоднородных данных. Например, в случае линейной регрессии масштабирование позволяет правильно интерпретировать коэффициенты значимости. Если не провести масштабирование, то веса модели будут некорректно отображать вклад каждого признака в результат. Также разный масштаб признаков может сильно затруднить обучение модели или сделать его невозможным. Это справедливо и для других моделей — например, для кластеризации, о которой вы узнаете из следующих уроков.

Данные масштабируют разными способами. В этом уроке вы рассмотрите два: стандартизацию и нормализацию.

Сначала разберёмся, что это за способы и чем они отличаются. Потом поговорим о том, в каких случаях какой способ лучше подходит. Обсудим, почему для обучения моделей данные сначала разделяются на **обучающую (train)** и **валидационную (test)**, а потом масштабируются.

Идея нормализации проста: преобразовать значения признака так, чтобы они оказались в заранее заданном промежутке значений. Обычно — от нуля до единицы.

Формула нормализации:

xnorm=xi−xminxmax−xmin,xnorm​=xmax​−xmin​xi​−xmin​​,

- xixi​ — значение признака;
- xminxmin​ — минимальное значение признака (обычно ноль)
- xmaxxmax​ — максимальное значение признака (обычно единица).

Посмотрите как это работает в коде.

Вот значения некоторой переменной, отображённые на числовой оси:

y = np.ones(len(x))

# рисуем график
plt.plot(x, y, 'o')

# задаём параметры графика
plt.xlabel('Значения переменной')
plt.yticks([])
plt.title('')

Теперь нормализуем их:

```
import matplotlib.pyplot as plt
import numpy as np
import pandas as pd

# значения переменной x

x = pd.Series([118, 284, 201, 303, 364, 256, 277, 252, 160, 189, 104, 240])
y = np.ones(len(x))

# нормализация:
x_norm = (x - min(x)) / (max(x) - min(x))

# рисуем график
plt.plot(x_norm, y, 'o')

Если применить нормализацию к нескольким переменным, имеющим разный размах, мы приведём их к единому масштабу, не потеряв при этом информацию.

> Если взять две переменных — в каждой по несколько разных значений — и нормализовать их на промежуток от 0 до 1, будет верно следующее (отметьте все верные утверждения):
> 
> Минимум обеих масштабированных переменных будет равен нулю.
> Масштабирование перенесёт минимум на левую границу заданного интервала.
> 
> Максимум обеих масштабированных переменных будет равен единице.
> Масштабирование перенесёт максимум на правую границу заданного интервала.

### Стандартизация

Тут данные преобразуются так, чтобы у них было одинаковое среднее значение и одинаковое стандартное отклонение вокруг этого среднего.

Чаще всего в машинном обучении средним берётся ноль, а стандартным отклонением — единица.

Формула для стандартизации признаков — отнимаем среднее от каждого значения набора данных, сдвигая таким образом среднее в ноль, а затем делим на стандартное отклонение этого набора, так приводим стандартное отклонение к единице:

xstandart=xi−xˉsx,xstandart​=sx​xi​−xˉ​,

где:

- xixi​ — каждое значение переменной;
- xˉxˉ — среднее значение набора данных;
- sxsx​ — стандартное отклонение набора данных.

Посмотрим в коде:

```
import matplotlib.pyplot as plt
import numpy as np
import pandas as pd

# значения переменной x
# (y нужен только чтобы отобразить график, зададим его как все единицы)
x = pd.Series([118, 284, 201, 303, 364, 256, 277, 252, 160, 189, 104, 240])
y = np.ones(len(x))

# стандартизация:
x_st = (x - np.mean(x)) / np.std(x)

# рисуем график
plt.plot(x_st, y, 'o')

# задаём параметры графика
plt.xlabel('Значения переменной')
plt.yticks([])
plt.title('')

# показываем график
plt.show() 
```

> Если взять две переменных — в каждой по несколько разных значений — и стандартизовать их, будет верно следующее (отметьте все верные утверждения):
> 
> Средние обеих масштабированных переменных будут равны.
> Стандартизация перенесёт среднее в ноль и приведёт к одинаковому значению стандартные отклонения. Но распределения останутся такими как были, — масштабирование не меняет вид графика. И в этом случае минимумы и максимумы заранее не предписаны.
> 
> Стандартные отклонения обеих масштабированных переменных будут равны.
> Стандартизация перенесёт среднее в ноль и приведёт к одинаковому значению стандартные отклонения. Но распределения останутся такими как были, — масштабирование не меняет вид графика. И в этом случае минимумы и максимумы заранее не предписаны.

### Какой метод масштабирования выбрать?

Нет строгого ответа на вопрос, когда лучше стандартизировать данные, когда — нормализировать, а когда выбирать какой-то другой метод.

Общая рекомендация

Если переменная распределена близко к нормальному, и принимает множество разных значений, чаще применяется стандартизация. А если у переменной всего несколько значений — например, это бинарная переменная (0 или 1) или категориальная переменная, перекодированная в числа — делают нормализацию.

### Проблема утечки

Для тренировки моделей машинного обучения вы обычно разбиваете выборку на обучающую и валидационную. Важное правило — не масштабируйте тренировочные и тестовые данные одновременно! Если сразу масштабировать весь датасет, то произойдёт утечка данных: тренировочная и тестовая выборки будут обладать общими свойствами. Тогда результат модели на этапе тестирования станет завышенным: будет казаться, что модель лучше, чем на самом деле.

Например, если не разделить данные перед стандартизацией, то среднее значение и стандартное отклонение будут рассчитаны на основе всего датасета. Из-за этого модель уже на этапе обучения «увидит» тестовые данные, и качество модели во время теста будет неоправданно завышено.

Поэтому алгоритм стандартизации такой:

- рассчитывают среднее и стандартное отклонение на обучающей выборке и преобразуют данные;
- применяют стандартизацию с полученными на обучающей выборке средним и стандартным отклонением к валидационной выборке;
- обучают модель на стандартизированных данных из обучающей выборки;
- делают прогноз для стандартизированных данных на валидационной выборке.

### Метод StandardScaler из библиотеки sklearn

Вместо того, чтобы прописывать формулу вручную, часто используют готовое решение — метод `StandardScaler` из библиотеки `sklearn`.

Предположим, вы уже разбили датасет на обучающую и валидационную подвыборки, и обучающую назвали `X_train`, а валидационную — `X_test`.

Обратите внимание, что `X_train` и `X_test` — это двумерные массивы:

![](https://pictures.s3.yandex.net/resources/G_4_1715529477.png)

Вот как можно стандартизировать такие данные с помощью `StandardScaler`:

```
# импорт функции
from sklearn.preprocessing import StandardScaler

# выбор метода масштабирования
scaler = StandardScaler()

# настройка масштабирования на тренировочной выборке -
# вычисление среднего и стандартного отклонения:
scaler.fit(X_train)

# масштабирование тренировочной выборки
X_train_scaled = scaler.transform(X_train)

# масштабирование тестовой выборки
X_test_scaled = scaler.transform(X_test) 
```

Проверим, что `StandardScaler` даст тот же результат, что и стандартизация, проведённая вручную:

import matplotlib.pyplot as plt

scaler.fit(x_2d)
# масштабирование тренировочной выборки
x_scaled = scaler.transform(x_2d)

# стандартизация вручную:
x_st = (x - np.mean(x)) / np.std(x)

# рисуем график результата ручной стандартизации
plt.plot(x_st, y, 's')
# рисуем график результата стандартизации StandardScaler
# (возьмем только одну из двух одинаковых переменных)
plt.plot(x_scaled, y, '.')

# задаём параметры графика
plt.xlabel('Значения переменной')

plt.title('')
