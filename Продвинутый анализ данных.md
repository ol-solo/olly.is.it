# Получение и сохранение данных
## Работа с файлами
В процессе работы бывает нужно проанализировать произвольные файлы с текстовой информацией или поработать с файлами внутри архива. В этом уроке мы узнаем, как функция `open` помогает читать и записывать файлы, научимся работать с файловой системой, а также поймём, как работать с архивными файлами через модуль `zipfile`. Это поможет понять, как аналитики могут организовывать и хранить данные.

### Открываем файлы

Функция `open` в Python используется для открытия файла. Она обращается к файловой системе и создаёт объект, который предоставляет методы для чтения или записи. Эта функция принимает два основных аргумента: имя файла и режим открытия, такой как `'r'` (read) для чтения, `'w'` (write) для полной перезаписи содержимого файла или его создания, `'a'` (append) для того, чтобы добавить содержимое в конец файла. Открыть и прочитать содержимое небольшого файла можно так:

```
file = open('example.txt', 'r')
content = file.read()
print(content)
file.close() 
```

В этом случае после чтения содержимого файла связанный с ним объект необходимо закрыть вызовом `file.close()` для освобождения системных ресурсов. Так вы показываете программе, что больше не будете обращаться к файлу.

Конструкция `with...as` упрощает управление файлами, обеспечивая автоматическое закрытие файла после выхода из блока `with`. Это делает код более чистым и безопасным:

```
with open('example.txt', 'r') as file:
    content = file.read()
    print(content) 
```

Этот код имеет такое же действие, как и код выше. Здесь файл автоматически закрывается после завершения чтения, и не нужно беспокоиться о закрытии файла вручную.

### Создаём текстовый файл

Иногда бывает необходимо создать файл с произвольным содержимым и сохранить его на диск. Откроем и перезапишем или создадим файл при помощи функции`open` в режиме записи (`"w"`) и сохраним в него имеющийся у нас текст:

```
content = """Ежедневный отчёт по продажам:
Дата: 21 мая 2024 года
Общее количество продаж: 150
Общая сумма продаж: 25,000

Основные категории товаров:
1. Электроника - 50 продаж
2. Одежда - 30 продаж
3. Бытовая техника - 70 продаж

Замечания:
- Увеличение продаж бытовой техники на 20% по сравнению с предыдущим днём.
- Снижение продаж одежды на 10%."""

with open('example.txt', 'w') as file:
    file.write(content) 
```

В данном случае создаётся файл `example.txt` и в него записывается текст из переменной `content`. Функция `write` записывает текст в файл, а использование конструкции `with...as` нужно, чтобы файл корректно закрылся после завершения записи.

### Построчная обработка данных

Не всегда полностью читать файл это хорошая идея, особенно если файл очень большой. У нас есть логи сервера `server.log`, если логи собираются за длительный срок, они могут достигать значительных объёмов. Чтобы понять, как автоматически проанализировать логи построчно, откроем такой файл со следующим содержимым:

```
2024-05-14 08:00:00 INFO Server started.
2024-05-14 08:15:23 ERROR Failed to connect to database.
2024-05-14 09:00:17 INFO New user registered.
2024-05-14 09:17:45 ERROR Timeout occurred processing request. 
```

Для того, чтобы перебрать строки файла, необходимо начать цикл, итерируясь по объекту файла. Внутри цикла мы перебираем каждую строку файла, проверяя наличие слова "ERROR". Если строка содержит это слово, она добавляется в список `errors` после удаления пробелов и символов новой строки с помощью метода `strip()`. В полученном списке подсчитываем число элементов и выводим его на экран:

```
errors = []
with open('server.log', 'r') as file:
    for line in file:
        if "ERROR" in line:
            errors.append(line.strip())

print(f"Найдено ошибок: {len(errors)}") 
```

```
Всего ошибок в логах: 2 
```

### Открываем много файлов

Не всегда мы знаем точно название файла, который нам нужно открыть. Также, зачастую в процессе работы приходится иметь дело не с одним и не с двумя файлами, а с большим их количеством. Например, каждый день филиал присылает файл, имя которого начинается с `report_` и заканчивается на `.xlsx` и нам нужно обработать все эти файлы. Сначала найдём все такие файлы. В этом нам поможет библиотека `os`. Её метод `listdir` позволяет получить содержимое указанной папки. Строкой из одной точки обычно обозначается текущая папка.

```
import os

reports = [f for f in os.listdir('.') 
            if f.startswith('report_') and f.endswith('.xlsx')] 
```

В переменную `reports` теперь помещён список названий файлов `['report_2024-05-06.xlsx', 'report_2024-05-07.xlsx', 'report_2024-05-08.xlsx', 'report_2024-05-09.xlsx', 'report_2024-05-10.xlsx']` с названиями ежедневных отчётов за предыдущую неделю. Теперь мы можем обработать их в цикле необходимым образом.

Для открытия отчётов нам потребуется метод Pandas `read_excel`. Отчёт типовой, сверху у него шапка, снизу место для подписей сотрудников, посередине данные. Пропустить строки шапки нам поможет параметр `skiprows`, он принимает список строк, начиная с нуля, которые нужно пропустить. Пропустить окончание документа нам поможет параметр `skipfooter`, он принимает одно число — количество строк в конце документа, которые не нужно загружать.

У отчёта много объединённых ячеек и не каждый столбец содержит данные. Так как нужные нам столбцы у отчёта не меняются, мы указываем их в нотации Excel в параметре `usecols`, где можем использовать как отдельные столбцы, так и их диапазоны. После загрузки отчёта метод `set_axis` с параметром `axis=1` позволит нам задать названия столбцам загружаемого датафрейма. Важно изменять список новых названий согласованно со значением, передаваемым в `usecols`. Весь пример кода загрузки датасетов в цикле целиком:

```
import pandas as pd

# Для каждого названия файла отчёта
for report in reports:
    # Открываем файл с таблицей
    df_raw = pd.read_excel(
        report,
        # Пропускаем шапку отчёта из 35 строк
        skiprows=range(35),
        # Пропускаем последние 10 строк документа
        skipfooter=10,
        # Используем заранее известные столбцы
        usecols="K:L,AY,BF,BU,CJ")\
        .set_axis(
            # Задаём названия оси таблицы 
            [   "Раздел", 
                "Показатель", 
                "Код показателя", 
                "Текущий год", 
                "Предыдущий год", 
                "Предшествующий предыдущему"],
            # Заменяем названия колонок
            axis=1) 
```

Далее нам может потребоваться предобработка данных и расчёт каких-то показателей. Информацию можно брать не только из таблицы: само имя файла `report` у нас содержало дату — её можно извлечь и сохранить, чтобы потом анализировать динамику метрик.

### Работаем с архивами

Библиотека `zipfile` в Python предоставляет возможности для работы с ZIP-архивами, включая возможности их создания, чтения, записи, а также извлечения содержимого. Допустим, что в конце предыдущего раздела мы подготовили сводный отчёт и сохранили его на диске под названием `consolidated_report.xlsx`. Этот файл вместе с отчётами за отдельные дни нам нужно добавлять в архив. Так как предыдущие действия мы автоматизировали, попробуем автоматизировать и это! Помня, что файлы продолжают лежать в той же папке, в которой мы запускаем скрипт, сделаем это при помощи модуля `zipfile`:

```
import zipfile

with zipfile.ZipFile('reports_archive.zip', 'w', zipfile.ZIP_DEFLATED) as archive:
    for report in reports:
        archive.write(report)
    else:
        archive.write('consolidated_report.xlsx') 
```

Конструкция `else` после циклов отрабатывает в случае успешного завершения цикла. Ура, теперь всё сохранили, можем отсылать! Обратите внимание, `zipfile` по умолчанию не сжимает файлы при создании архива, поэтому мы указываем тип сжатия `zipfile.ZIP_DEFLATED`.

### Автоматизация процессов с помощью чтения ZIP-архивов

Текстовые форматы хранения данных, например формат `csv`, могут очень быстро прибавлять в объёме по мере добавления данных, но они обычно хорошо сжимаются. Очень часто такие файлы распространяются в запакованном виде.

Выше мы записывали файлы в архив, но архивы иногда бывает необходимо читать. Используем библиотеку `zipfile` для этого.

Для более надёжной и безопасной работы с файлами и архивами используем использовавшуюся выше конструкцию `with...as`, причём сделаем её вложенной. Конструкция гарантирует, что файл и архив будут корректно закрыты после завершения нужных операций.

Например, внутри архива расположен файл `purchases.csv`, который выглядит следующим образом:

```
PurchaseID,Amount
001,25.50
002,45.00
003,17.75
004,34.00 
```

Используем модуль `zipfile` для открытия архива `monthly_data.zip` с помощью конструкции `with...as`. Затем внутри архива открываем файл `purchases.csv`. Первую строку файла, содержащую заголовки, проверяем с помощью функции `next(file)` и конструкции `assert` на соответствие ожидаемому значению. В случае несоответствия заголовков `assert` выведет сообщение об ошибке. Файл для Python — это набор байтов, как и отдельные его части, поэтому мы ставим `b` перед строкой.

Используя генераторное выражение внутри функции `sum`, подсчитываем количество строк, которое соответствует количеству покупок. В конце результат выводится на экран.

```
import zipfile

# Открытие ZIP-архива и чтение содержимого CSV-файла внутри
with zipfile.ZipFile('purchases.zip', 'r') as archive:
    with archive.open('purchases.csv') as file:
        assert next(file) == b'PurchaseID,Amount\n', \
            'Заголовки файла не соответствуют ожидаемым'
        # Подсчёт количества строк и покупок
        total_purchases = sum(1 for _ in file)

print(f"Общее количество покупок: {total_purchases}") 
```

Мы научились добавлять файлы в архивы и открывать текстовые файлы в Python, даже если они запакованы. Если есть возможность импортировать библиотеку pandas и в архиве лежит всего один файл csv, то можно использовать привычный метод `read_csv`. Однако для других случаев удобно знать другие методы открытия текстовых данных.

### Запуск кода

C тем, **какой** код запускать мы разобрались, но чтобы автоматизация была удобной, надо придумать, **как** его запускать. Работа в Python может быть весьма разнообразной, как и задачи, которые решаются с его помощью.

Основными форматами файлов в Python считаются `.py`, они используются для создания и запуска собранных программ и проектов. Файлы `.ipynb` применяются для интерактивного выполнения кода и ведения журнала вычислений в удобном интерфейсе Jupyter Notebook, так как они удобнее для написания кода, особенно если его нужно кому-то передавать. Однако для запуска небольшого скрипта тетрадки Jupyter Notebook подходят хуже.

Если скрипт выше сохранён в файле `purchases.py` и на компьютере установлен Python, то достаточно в командной строке ввести `python purchases.py`, чтобы увидеть результат: `Общее количество покупок: 4`.

Вы можете использовать подходящие для вашей системы планировщики запуска скриптов для автоматизации рабочих задач.

## Работа с таблицами
Аналитика начинается с данных. Бывает, что они хранятся уже в готовых csv/tsv-файлах и вы используете метод `read_csv()`, чтобы превратить таблицы в датафреймы. Бывает, что данные хранятся в Excel-файле, но и это уже нестрашно и вы вызываете метод `read_excel()`.

Так или иначе, всё это время вы работали с таблицами, которые хранятся на вашем компьютере, перед этим скачивая их по ссылке.

Но что делать, если таблица с данными, которые вам нужны, хранится где-то в интернете, на веб-странице, а кнопки `скачать` просто нет?

### Сайты тоже хранят данные

Переходя по ссылке на любой из сайтов, ваш браузер всегда начинает с того, что скачивает файлы, это называют загрузкой сайта. Все файлы, которые скачивает браузер, делятся на несколько типов, вот самые важные:

- `html` — получая такой файл, браузер понимает, как должна выглядеть страница сайта для пользователя, и начинает её отрисовку. `html`-файл говорит браузеру, как именно нарисовать страницу сайта и что она будет содержать. По сути, это разметка с содержимым, как Markdown в jupyter-третрадке, но посложнее. Именно об этом файле мы сегодня поговорим.
- `png/jpg/gif` и прочее — это картинки, которые сопровождают вас почти всегда: логотип сайта, видеолендинг. Это называют ассетами.
- `js` — это те файлы, которые говорят браузеру, что нужно делать, когда начинаете взаимодействовать с сайтом: кликать, скроллить или печатать.

Всё содержимое страницы сайта хранится в `html`-файле, и выглядит он примерно так:

```
<!DOCTYPE html>
<html>
<head>
  <title>Мой первый веб-сайт</title>
</head>
<body>
  <header>
    <h1>Добро пожаловать на мой сайт!</h1>
    <nav>
      <ul>
        <li><a href="#">Главная</a></li>
        <li><a href="#">О нас</a></li>
        <li><a href="#">Услуги</a></li>
        <li><a href="#">Контакты</a></li>
      </ul>
    </nav>
  </header>
  
... 
```

Попробуем прочитать эти данные прямо с сайта, но используя Pandas. Для этого воспользуемся методом `read_html()`, указывая параметром только адрес URL-ссылки на страницу. Этот метод исследует html-файл страницы и пытается найти всё, что похоже на таблицу, и превратить в датафрейм. Строку подаём сразу в зашифрованном виде (`%D0%A7`…), скопировав из адресной строки браузера.

## Подготовка графики

Для использования графиков в документах важно корректно их сохранить в файле с графическим форматом, чтобы визуализация была информативной и правильно оформленной. В прошлых уроках вы узнали, какие элементы стоит отобразить на графике, чтобы он был максимально информативным: задать заголовок, подпись по осям, легенду и другую необходимую информацию. Ещё вы изучили, как изменить размер графика, сохранить визуализацию в отдельном графике, выбрать корректный формат и разрешение файла, а также настроить отображение всех элементов графика.

В этом уроке мы рассмотрим особенности отображения и сохранения визуализаций в виде отдельных графических файлов:

- как настроить размер шрифтов;
- как вместить все элементы графика в сохраняемую область и избежать их пересечения;

Для примера будем использовать графики с динамикой кумулятивных метрик, которые вы разбирали в предыдущих спринтах.

### Меняем размер графика и размер шрифта

В текстовый файл или презентацию графические файлы вставляются в виде изображения с заданным размером — в сантиметрах или дюймах. А также с установленным разрешением — количеством точек на дюйм.

По умолчанию графики, построенные с использованием распространённых библиотек визуализаций matplotlib и seaborn, имеют размер 6.4 на 4.8 дюйма, или примерно 16 на 12 см. Этого размера хватит, чтобы вставить визуализацию в текст на странице формата А4 или в страницу презентации. При работе с данными в тетрадке Jupyter Notebook размеры графиков часто увеличивают — это повышает информативность визуализации. Для этого используют параметр `figsize=()` метода `plt.figure()`, где задаются два значения: первое — размер графика по ширине, а второе — размер по высоте. Размеры задают в дюймах.

При подготовке графика к публикации следует не ставить размер больше свободного места на странице текста или слайде в презентации, поскольку в этом случае визуализация будет масштабирована под размер страницы. Как правило, для текстовых файлов используется лист формата А4, имеющий размер 210 на 297 мм, или 8.3 на 11.7 дюймов. Поэтому с учётом полей страницы желательно, чтобы размер сохраняемого графика не превышал 18 см по ширине страницы и 27 см по её высоте.

В большинстве случаев текстовые документы имеют альбомную ориентацию — можно взять за ограничение ширины графика 18 см, или около 7 дюймов по ширине. В таком случае задаваемые размеры шрифтов для подписи заголовка графика или его осей будут соответствовать распространённым размерам шрифтов в текстовых редакторах.

Разберём на примере графика кумулятивного значения среднего количества покупок на покупателя. Вначале рассчитаем необходимые метрики:

```
# Импортируем необходимые библиотеки:
import pandas as pd
from matplotlib import pyplot as plt
import seaborn as sns

# Загрузим данные с результатом теста:
orders = pd.read_csv('https://code.s3.yandex.net/datasets/orders_us.csv')
orders['date'] = pd.to_datetime(orders['date'])

# Найдём минимальную и максимальную даты сбора статистики:
start_date = orders['date'].min()
end_date = orders['date'].max()

# Создадим последовательность дат проведения теста:
test_dates = pd.date_range(start=start_date, end=end_date, freq='1D')

# Создадим пустой датафрейм с двумя столбцами — группами теста:
cum_avg_purchases = pd.DataFrame(columns = ['A', 'B'])

# Зададим цикл, перебирающий последовательность дат:
for i, date in enumerate(test_dates):
    current_purchases = (orders.query('date <= @date')
         # Для каждого пользователя в группах найдём количество заказов:
          .groupby(['group','visitorId'])
          .agg({'transactionId': 'nunique'}).reset_index()
         # Для каждой группы подсчитаем среднее количество заказов:
          .groupby('group')
          .agg({'transactionId': 'mean'}).T
        )

    # Добавим информацию о дате и дне проведения теста:
    current_purchases['date'] = date
    current_purchases['test_day'] = i

    # Добавим данные к датафрейму cum_revenue:
    cum_avg_purchases = pd.concat([cum_avg_purchases, current_purchases],
                                  ignore_index=True)

# Подсчитаем относительное значение метрики в группе В по отношению к группе А
cum_avg_purchases['rel_BA'] = cum_avg_purchases['B'] / cum_avg_purchases['A'] - 1 
```

А затем начнём строить график динамики отношения значений кумулятивного количества заказов на пользователя в группе В по отношению к группе А. Зададим размер графика, равный 7 на 4 дюйма:

```
# Визуализируем результаты:
plt.figure(figsize=(7, 4))
sns.lineplot(x='date', 
             y='rel_BA', 
             data=cum_avg_purchases, 
             label='Отношение группы В к группе А')

plt.show() 
```

### Сохранение графика

График готов. Для дальнейшего использования его стоит сохранить в виде отдельного графического файла.

Графические данные могут быть представлены в различных форматах:

- Растровое изображение, представленное в виде набора пикселей и раскрашенное в определённые цвета. Например, если размер картинки 100 на 100 пикселей, то изображение будет состоять из 100х100 или 10 000 пикселей. В таком формате хранится большая часть изображений, например фотографии в телефоне.
- Векторное изображение, для которого прописаны правила отображения: с такого-то места до такого провести линию синего цвета или в таком месте нарисовать красный круг заданного диаметра. Такой формат хорошо подходит для отображения схематичных рисунков или графиков.

Графики в Python можно сохранить изображение как в растровом, так и в векторном виде:

- в растровом виде, например с расширением `png` или `jpg`;
- в векторном формате `svg`;
- В формате `pdf`.

Для сохранения визуализации, созданной на основе matplotlib, используется метод `plt.savefig()`. Для быстрого сохранения графика с базовыми настройками достаточно передать методу в качестве аргумента название файла:

```
# Сохраним визуализацию в формате PNG: 
plt.savefig("my_first_plot.png")  
```

Визуализация сохранилась с базовыми настройками в файл, расположенный в корневом каталоге тетрадки Jupyter Notebook. Метод `plt.savefig()` имеет ещё несколько параметров, которые могут быть полезными при сохранении визуализаций:

- `dpi` — параметр задаёт размер разрешения — количества точек дюйм. Чем выше это значение — тем более чёткое изображение, но и тем больше размер файла с изображением. По умолчанию стоит размер 100 `dpi`. Этого вполне достаточно для отображения графика на экране монитора. Однако для демонстрации на большом экране при сохранении в растровом формате или при распечатывании отчёта на бумажном носителе лучше увеличить это значение до 200 или 300 точек на дюйм.
- `transparent` — параметр, определяющий прозрачность контейнера визуализации. Такой эффект доступен для растрового формата `png`. В расширении `jpg` установить прозрачность не получится, поскольку этот формат не поддерживает такой опции. Значение `True` — позволяет сделать график прозрачным, тогда как значение `False`, используемое по умолчанию, делает контейнер с изображением непрозрачным и по умолчанию — белым.

Например, сохраним график с разрешением 300 DPI и включённой прозрачностью:
```python
plt.savefig("my_first_plot.png", dpi=300, transparent=True)
```

### Сохранение сабплотов и проблема пересечения элементов графика

Иногда для отображения результатов аналитики используют несколько графиков на одной визуализации. Или несколько «сабплотов». При сохранении таких графиков есть свои особенности. Поскольку в одном графике включается несколько, то общий размер контейнера со всеми графиками увеличивают, например, до 12 дюймов.

Рассмотрим на примере, добавим график с накопительным значением метрик для двух групп:

```
# Создание фигуры и осей для сабплотов
fig, ax = plt.subplots(nrows=1, ncols=2, figsize=(12, 5))

# Динамика кумулятивного значения метрики в группе А и В:
sns.lineplot(x='date', y='A', data=cum_avg_purchases, label='Группа А', ax=ax[0])
sns.lineplot(x='date', y='B', data=cum_avg_purchases, label='Группа B', ax=ax[0])

# Добавим форматирование графика:
```

## Формат данных JSON
Мы уже касались данной темы в дополнительных материалах предыдущего модуля.

JSON (JavaScript Object Notation) стал неотъемлемой частью современного анализа данных. Это текстовый формат, который используется для представления структурированных данных и который основан на синтаксисе JavaScript.

JSON стал популярным благодаря своей простоте, лёгкости и читабельности как для человека, так и для машины. В мире данных JSON используется повсеместно, и умение работать с ним считается важным навыком для аналитика данных.

В этом уроке вы узнаете, как использовать библиотеку `json` для конвертации объектов Python в JSON-строку и обратно. Обсудим конкретные случаи, когда аналитику данных нужно работать с JSON. Этот урок поможет вам освоить базовые техники работы с таким форматом данных.

В Python JSON-объекты очень схожи со словарями (dict), что облегчает их использование. Рассмотрим некоторые ключевые моменты:

- **структура:** JSON представляет собой пары «ключ-значение», что аналогично структуре словаря в Python;
- **типы данных:** JSON поддерживает простые типы данных, такие как строки, числа, массивы (списки в Python), и вложенные объекты (словари в Python);
- **чтение и запись:** в Python существует встроенная библиотека **`json`**, которая предоставляет простые методы для преобразования данных между JSON- и Python-объектами.

Пример словаря в Python:

```
data = {
    "name": "John",
    "age": 30,
    "city": "New York",
    "children": ["Ann", "Billy"]
} 
```

Эквивалент в JSON:

```
{
    "name": "John",
    "age": 30,
    "city": "New York",
    "children": ["Ann", "Billy"]
} 
```

### **В каких случаях аналитику нужно работать с данными в формате JSON**

1. **Веб-API:** Большинство современных веб-API возвращают данные в формате JSON. Если аналитик взаимодействует с API для получения данных, например, от социальных сетей, финансовых сервисов или метеорологических служб, ему потребуется умение читать и обрабатывать JSON. **Пример JSON-ответа от API социальной сети:**
    
    ```
     {
         "user": {
             "id": 12345,
             "name": "John Doe",
             "followers": 150,
             "posts": [
                 {
                     "id": 54321,
                     "content": "Hello, world!",
                     "likes": 10,
                     "comments": [
                         {"id": 1, "user": "Alice", "text": "Great post!"},
                         {"id": 2, "user": "Bob", "text": "Thanks for sharing!"}
                     ]
                 }
             ]
         }
     }
      
    ```
    
2. **Хранение и передача данных:** JSON широко используется для хранения конфигураций и настроек, а также для передачи данных между различными системами. Это делает JSON незаменимым для интеграции данных из разных источников и систем. **Пример JSON-файла конфигурации:**

    
3. **Базы данных NoSQL:** Многие современные базы данных NoSQL, такие как MongoDB, используют формат, схожий с JSON (BSON). Понимание JSON помогает аналитику эффективно работать с такими базами данных. **Пример документа в базе данных MongoDB:**
    

Освоение работы с JSON даёт аналитику возможность решать широкий спектр задач, от получения данных через API до их хранения и последующей обработки. Далее мы рассмотрим, как преобразовывать объекты Python в JSON и обратно, что считается основой для дальнейшей работы с этим форматом.

### **Преобразование объектов Python в JSON**

Для преобразования объектов Python (например, словарей и списков) в JSON-строку используется функция **`json.dumps()`** из встроенной библиотеки **`json`**.

Пример:

```
import json

# Создаём объект в формате словаря Python
data = {
    "name": "Alice",
    "age": 25,
    "city": "London",
    "languages": ["English", "Spanish"]
}

# Преобразуем объект в JSON-строку
json_string = json.dumps(data)
print(json_string) 
```

Итоговый результат:

```
{"name": "Alice", "age": 25, "city": "London", "languages": ["English", "Spanish"]} 
```

### **Преобразование JSON-строки в объект Python**

Для преобразования JSON-строки обратно в объект Python используется функция **`json.loads()`**.

Пример:

```
import json

# Определим JSON-строку
json_string = '{"name": "Alice", "age": 25, "city": "London", "languages": ["English", "Spanish"]}'

# Преобразуем JSON-строку в объект Python
data = json.loads(json_string)
print(data)
# Выводим тип данных полученного объекта
print(f'Тип данных: {type(data)}') 
```

Итоговый результат:

```
{'name': 'Alice', 'age': 25, 'city': 'London', 'languages': ['English', 'Spanish']}
Тип данных: <class 'dict'> 
```

Умение преобразовывать объекты Python в JSON и обратно считается важным навыком для аналитика данных. Это позволяет эффективно работать с данными, полученными из различных источников: веб-API, базами данных и файлами конфигураций.

Внутри JSON-строки мы использовали двойные кавычки для обозначения текста — это единственный возможный вариант, другие дадут ошибку. Если двойная кавычка есть внутри передаваемой строки, то используется экранирование.

## Принципы работы с API
Сегодня в мире, где полно разнообразных веб-сервисов и приложений, программные интерфейсы (API) играют ключевую роль. API обеспечивают взаимодействие между различными системами и платформами: позволяют приложениям обмениваться данными и функциональностью и делают возможными интеграцию и автоматизацию процессов. Для аналитиков данных умение работать с API — важный навык, потому что многие источники данных предоставляют информацию именно через API.

В этом разделе вы познакомитесь с основами работы через API, научитесь отправлять запросы, получать и обрабатывать данные в формате JSON. Затем преобразовывать эти данные в удобные для анализа форматы, такие как pandas DataFrame.

Для начала стоит разобрать общие принципы работы API. Вы узнаете, как использовать библиотеку Requests, чтобы отправлять запросы и получать ответы.

### Что такое API?

**API (Application Programming Interface)** — это набор инструментов и протоколов, который позволяет различным программным приложениям взаимодействовать между собой.

API предоставляет методы и правила для обмена данными и выполнения операций, чтобы разработчики могли использовать функциональность одного приложения в другом. Это особенно важно в условиях, когда различные системы и приложения должны работать совместно. Так обеспечивается эффективная передача данных и функциональность.

Существует несколько типов API — каждый имеет свои особенности и области применения. Вот основные:

1. **REST (Representational State Transfer)** **API** — протокол обмена сообщениями, который использует стандартные методы HTTP (GET, POST, PUT, DELETE) для взаимодействия с ресурсами. Каждый ресурс идентифицируется уникальным URL.
2. **SOAP (Simple Object Access Protocol)** **API** — протокол обмена сообщениями, который использует XML для кодирования запросов и ответов. SOAP работает по различным протоколам передачи данных, таким как HTTP, SMTP и другие.

В современных веб-разработке и анализе данных наиболее популярен REST API. Именно через него многие крупные компании и сервисы предоставляют свои данные и функциональные возможности. Так как доступ к этим данным часто необходим для анализа и принятия решений, знание REST API — важный навык для аналитиков данных.

Взаимодействие с API происходит таким образом: вы отправляете HTTP-запрос и получаете ответ. Запросы могут содержать параметры и заголовки.

REST API часто возвращает данные в формате JSON, который легко парсится в Python. Этот формат стал стандартом для обмена данными в веб-приложениях благодаря своей простоте и гибкости.

HTTP-ответы содержат статусные коды, которые указывают на успешность или неуспешность запроса. Вы наверняка сталкивались с кодом 404 — «страница не найдена». Это HTTP-ответ. Код 200, например, обозначает успешный запрос, а 500 — ошибку сервера.

### **Принципы работы с библиотекой Requests**

Библиотеку Requests в Python используют для отправки HTTP-запросов. Вот основные методы и их синтаксис:

**GET-запрос** используется для получения данных с сервера. Это самый распространённый тип запроса, который не изменяет состояние ресурса (`resource`) на сервере.

```
response = requests.get('https://api.example.com/resource') 
```

**POST-запрос** нужен для отправки данных на сервер с целью создания новых данных. В отличие от GET, этот запрос изменяет состояние ресурса.

```
response = requests.post('https://api.example.com/resource', 
                         data={'key': 'value'}) 
```

**PUT-запрос** используют, чтобы обновить существующий ресурс на сервере или создать новый, если ресурса не существует. PUT-запросы обычно отправляют все данные о ресурсе, даже если изменились только некоторые из них.

```
response = requests.put('https://api.example.com/resource', 
                        data={'key': 'value'}) 
```

**DELETE-запрос** удаляет ресурс с сервера.

```
response = requests.delete('https://api.example.com/resource') 
```

## Загрузка данных из базы SQL
В современном мире данные — это ключевой ресурс для принятия решений, прогнозирования и анализа. Умение подключаться к базам данных и извлекать данные с помощью Python — важнейший навык для аналитика.

Большинство организаций работают с огромными объемами информации, которые хранятся в базах данных. Эти данные могут включать в себя показатели о продажах, клиентах, продуктах, транзакциях и многом другом. Использование баз данных позволяет эффективно управлять и структурировать эту информацию.

Базы данных предоставляют централизованное хранилище для всех данных организации. Такие хранилища оптимизированы для быстрого поиска, извлечения и манипулирования сведениями. SQL-запросы позволяют извлекать необходимые данные быстро и эффективно.

В этом уроке мы рассмотрим, как Python может подключаться к базе данных, выполнять SQL-запросы и выгружать данные.

### **Подключение к базе данных и выполнения SQL-запросов**

В Python существует множество библиотек, которые могут использоваться для подключения к базам данных. Вот некоторые из них:

- **psycopg2 —** библиотека для работы с PostgreSQL;
- **PyMySQL** — библиотека для работы с MySQL;
- **SQLite (sqlite3)** — встроенная в Python библиотека для работы с SQLite;
- **PyODBC** — библиотека для работы с различными базами данных через ODBC (Open Database Connectivity — стандартный интерфейс для доступа к различным системам управления базами данных).

Для работы с базой данных в Python мы будем использовать библиотеку`SQLAlchemy`для создания подключения и библиотеку `pandas` для выполнения SQL-запросов и обработки данных.

`SQLAlchemy` — одна из самых популярных библиотек для работы с реляционными базами данных в Python. Она поддерживает множество баз данных: PostgreSQL, MySQL, SQLite, Oracle и многие другие. Это делает `SQLAlchemy` универсальным инструментом, который можно использовать в различных проектах.

**1. Импорт необходимых библиотек:**

```
import pandas as pd
from sqlalchemy import text, create_engine 
```

`create_engine` — это функция из библиотеки SQLAlchemy, которая используется для создания объекта «движка» (engine), представляющего соединение с базой данных. Этот объект считается основной точкой взаимодействия с базой данных, позволяя нам выполнять SQL-запросы, управлять транзакциями и работать с метаданными базы данных.

`text` — это функция из библиотеки SQLAlchemy, которая используется для создания SQL-запросов в виде строк. Она позволяет использовать «сырой» SQL, оборачивая строку запроса в объект, который можно безопасно передавать в методы выполнения запросов SQLAlchemy.

**2. Установка параметров подключения**

Следующим шагом будет установка параметров для подключения к базе данных:


Тут содержатся данные о том, куда подключаться, какой логин и пароль показывать и в какую базу данных заглядывать. Когда вы подключаетесь к базе данных, важно правильно настроить параметры подключения.

С именем пользователя и паролем всё понятно, давайте рассмотрим ключевые параметры: `host`, `port` и `db`, которые необходимы для установления соединения.

**`host`** — это параметр, указывающий на адрес сервера базы данных. Это может быть доменное имя (например, `example.com`) или IP-адрес (например, `192.168.1.1`), где хостится ваша база данных.

- **локальный хост**: если база данных установлена на вашем локальном компьютере, `host` часто будет `localhost` или `127.0.0.1`;
- **удаленный сервер**: если база данных находится на удаленном сервере, вы указываете адрес этого сервера. В нашем примере, это `rc1b-wcoijxj3yxfsf3fs.mdb.yandexcloud.net`.

**`port`** — это параметр, указывающий на порт, через который происходит подключение к серверу базы данных. Каждый тип базы данных обычно имеет стандартный порт, но он может быть изменен.

- **стандартные порты**: для PostgreSQL стандартный порт — 5432, для MySQL — 3306, для SQL Server — 1433 и так далее;
- **кастомные порты**: иногда администраторы баз данных меняют стандартные порты по соображениям безопасности или для предотвращения конфликтов.

**`db`** — это параметр, указывающий на имя конкретной базы данных, к которой вы хотите подключиться. На сервере базы данных может находиться несколько баз данных, и этот параметр помогает идентифицировать ту, с которой вы собираетесь работать. В нашем примере, это `data-analyst-final-project-db`.

**3. Создание строки подключения**

Используя параметры подключения, создадим строку подключения:

```
connection_string = 'postgresql://{user}:{pwd}@{host}:{port}/{db}'\
                        .format(**db_config) 
```

Тут `**` — оператор, обратный функции `dict`, он распаковывает словарь в команды для метода `format`.

**4. Создание коннектора**

С помощью строки подключения создадим объект коннектора:

```
engine = create_engine(connection_string, 
                       connect_args={'sslmode':'require'}) 
```

Параметр `connect_args={'sslmode':'require'}` используется при создании соединения с базой данных с помощью библиотеки SQLAlchemy. В этом случае параметр `sslmode` устанавливается в значение `require`, потому что при соединении требуется использование SSL (Secure Sockets Layer) для защищенного шифрования трафика между клиентом (вашим приложением Python) и сервером базы данных. Этот параметр обеспечивает безопасное и защищенное соединение с базой данных, особенно если данные чувствительные и конфиденциальные.

Параметр `sslmode` имеет несколько вариантов значений, которые определяют уровень безопасности соединения с базой данных. Вот основные из них:

- `disable` — отключает использование SSL. Соединение установится без шифрования;
- `allow` — попытка использовать SSL, если это поддерживается сервером, но если SSL недоступен, то соединение установится без него;
- `verify-ca` — требует использование SSL и проверку сертификата SSL, подписанного доверенным центром сертификации (CA). Сертификат сервера должен быть проверен.

**5. Выполнение SQL-запроса и выгрузка данных**


Объект `con` представляет собой соединение с базой данных через «движок» `engine.connect()` , который создан с помощью функции `create_engine`.

`pd.read_sql()` — это функция pandas, которая выполняет SQL-запрос к базе данных и загружает результаты в DataFrame.

`sql=text(query)` — здесь создается объект SQLAlchemy `text`, который представляет собой SQL-запрос в виде строки. Этот объект передается в `pd.read_sql()` в качестве аргумента `sql`.

Результаты SQL-запроса загружаются в DataFrame `df`, который можно использовать для анализа и обработки данных в Python.

### Изменение формата датасета

В своей работе аналитик часто переводит данные из одного формата в другой. Например, если данные представлены в виде длинной таблицы и необходимо провести анализ метрик по группам или сегментам. Для этого данные лучше подготовить в формате широкой таблицы. Так удобнее проводить агрегацию значений по столбцам.

Бывают обратные случаи, когда необходимо привести данные к длинному формату. Например, при подготовке визуализаций и создании дашбордов в популярных BI-системах.

_Метод `.unstack()` проводит преобразование уровней индексов датафрейма в уровни колонок._

Как следует из схемы, для применения преобразования длиной таблицы в широкую необходимо, чтобы исходная длинная таблица содержала ключевые значения в виде индексов, то есть используется мультииндекс строк.

В нашем примере мультииндекс будет содержать два индекса — номер пользователя `user_id` и значение параметра `parameter`. Один из них будет представлять собой уникальное наблюдения — `user_id`, а второй — содержать названия будущих столбцов, т.е. `parameter`. Уровней индексов в мультииндексе может быть больше, но общая логика остаётся: один из индексов (по умолчанию индекс, имеющий внутренний уровень) используется для создания столбцов, другие — в качестве индекса строк будущей широкой таблицы.

Если посмотреть на данные пользователей А/В-теста, то в качестве индекса строк выступают целочисленные значения, последовательно нумерующие строки:

```
            user_id parameter           value
0  0002CE61FF2C4011     group               A
1  0002CE61FF2C4011      test  interface_test
2  0002CE61FF2C4011    device             Mac
3  0002CE61FF2C4011    region              EU
4  0002CE61FF2C4011  reg_date      2021-01-18 
```

Такой индекс не подойдёт для преобразования таблицы в широкую. Поэтому следует отдельно задать индексы длинной таблице.

Для этого используем метод pandas `.set_index()`. Он позволяет задать датафрейму новый индекс. Если передать одно значение — индекс будет иметь один уровень, если передать список значений — многоуровневым, то есть мультииндексом. Передадим в качестве индекса список названий столбцов — `['user_id', 'parameter']`:

```
# Изменим индекс датафрейма с помощью метода .set_index():
df_long.set_index(['user_id', 'parameter'], inplace=True)

# Отобразим первые пять строк:
print(df_long.head())

# Отобразим имена индексов:
print(df_long.index.names) 
```

```
                                     value
user_id          parameter                
0002CE61FF2C4011 group                   A
                 test       interface_test
                 device                Mac
                 region                 EU
                 reg_date       2021-01-18
                 
['user_id', 'parameter'] 
```

Теперь данные представлены иначе — строки имеют два индекса: `user_id` и `parameter`, они представляют собой мультииндекс, где `parameter` является внутренним индексом.

С индексами разобрались, теперь можно приступить к трансформации таблицы из длинной в широкую. Для этого применим метод `.unstack()` с параметрами по умолчанию:

```
# Создадим широкий датафрейм на основе длинного:
df_wide = df_long.unstack()

# Отобразим первые пять строк:
print(df_wide.head()) 
```

```
user_id                                                           
0002CE61FF2C4011      Mac     A  2021-01-18     EU  interface_test
001E72F50D1C48FA      Mac     B  2021-01-28     EU  interface_test
002412F1EB3F6E38      Mac     A  2021-01-20     EU  interface_test
002540BE89C930FB  Android     A  2021-01-19     EU  interface_test
0031F1B5E9FBF708  Android     B  2021-01-25     EU  interface_test 
```

Сработало! Данные представлены в виде широкой таблицы. Метод `.unstack()` при работе проверяет, чтобы значения (в нашем случае столбец `value`) в данных были уникальными. Если для одного параметра одного наблюдения будет несколько значений — метод закончит работу с ошибкой.

Однако остался один момент — датафрейм имеет сложную систему мультииндекса столбца, что может быть не очень комфортно при анализе данных такого датафрейма, поскольку вместо названия столбца при агрегации или фильтрации данных может потребоваться указывать мультииндекс.

Выведем названия столбцов:

```
# Выведем индекс столбцов:
print(df_wide.columns) 
```

```
MultiIndex([('value',   'device'),
            ('value',    'group'),
            ('value', 'reg_date'),
            ('value',   'region'),
            ('value',     'test')],
           names=[None, 'parameter']) 
```

Столбцы имеют мультииндекс `[None, 'parameter']`, где верхний уровень без названия содержит значение `value`, а внутренний уровень `'parameter'` — информативные названия столбцов. Уберём этот уровень:

```
# Удалим верхний уровень индекса столбцов:
df_wide.columns = df_wide.columns.droplevel()

# Выведем индекс столбцов:
print(df_wide.columns) 
```

```
Index(['device', 'group', 'reg_date', 'region', 'test'], dtype='object', name='parameter') 
```

Для этого использовали метод pandas `.droplevel()`. Этот метод позволяет удалить уровни в индексе столбцов, по умолчанию — самый внешний уровень. После применения метода `.droplevel()` для индекса столбцов датафрейм будет представлен в таком виде:

```
# Отобразим первые пять строк:
```

Теперь датафрейм имеет вид, к которому мы привыкли при загрузке данных из внешних источников.

Существует длинный датафрейм с такими данными:

- `order_id` — номер заказа;
- `user_id` — идентификатор пользователя;
- `parameter` — в этом столбце содержатся категории данных, такие как количество товаров, стоимость заказа, дата заказа, время доставки;
- `value` — значения для каждого параметра.

Каждая строка содержит уникальные данные, индекс строк — их порядковый номер. Какой код позволит преобразовать данные из длинного формата в широкий, чтобы каждый параметр был в уникальном столбце?

```
df_long.set_index(['order_id', 'user_id', 'parameter']).unstack() 
``` 

Верно! В начале нужно задать мультииндекс — столбцы `order_id`, `user_id`, `parameter`. Метод `.unstack()` будет использовать по умолчанию самый внутренний индекс для преобразования данных — `parameter`.

Привести данные из длинной таблицы в широкую можно с помощью создания сводной таблицы — `.pivot_table()`:

```
# Создадим сводную таблицу с помощью метода .pivot_table():
df_wide = df_long.pivot_table(index='user_id', columns='parameter', 
                    values='value', aggfunc='first').reset_index()

# Сбросим название уровня индекса столбцов:
df_wide.columns.name = None

# Отобразим первые пять строк:
print(df_wide.head()) 
```

```
            user_id   device group    reg_date region            test
0  0002CE61FF2C4011      Mac     A  2021-01-18     EU  interface_test
1  001E72F50D1C48FA      Mac     B  2021-01-28     EU  interface_test
2  002412F1EB3F6E38      Mac     A  2021-01-20     EU  interface_test
3  002540BE89C930FB  Android     A  2021-01-19     EU  interface_test
4  0031F1B5E9FBF708  Android     B  2021-01-25     EU  interface_test 
```

Результат получился аналогичным. Для индекса будущей широкой таблицы были использованы значения столбца `user_id`, в качестве колонок — `parameter`, а значения — `value`. Поскольку метод `.pivot_table()` основан на агрегации данных, чтобы сводная таблица была создана в качестве параметра `aggfunc`, использовали метод `first`, определяющий первое обнаруженное значение параметра. Так как исходные данные в длинном формате содержали уникальные значения для каждого параметра, то первое встреченное значение для параметра и будет его уникальным значением. Если бы значения были представлены в числовом виде, то тогда можно было бы использовать значение `aggfunc` по умолчанию как рассчитывающее среднее.

Как видно, широкую таблицу можно преобразовать из длинной несколькими путями. Метод `.unstack()` удобен тем, что использует систему индексов датафрейма. При этом он не использует агрегацию данных, а преобразует структуру таблицы. С помощью сводной таблицы `.pivot_table()` также можно создать широкую таблицу, однако в этом случае необходимо задавать индексы, колонки и значения будущей широкой таблицы. При этом, если метод `.unstack()` при работе проверяет уникальность значений для каждого параметра, то при создании сводной таблицы используется агрегация данных, и нужно выбрать метод их агрегирования.

Однако

При использовании `.pivot_table()` для трансформации длинной таблицы в широкую стоит убедиться, что все значения для каждого параметра — уникальны. Иначе, если одно наблюдения для одного параметра будет иметь несколько значений, то вместо трансформации в широкую таблицу произойдёт агрегация данных. А это уже сводная таблица. По формату она будет широкой, но часть данных может потеряться, заменившись средним значением.

### Преобразование широкого формата в длинный

При работе с данными также бывают случаи, когда необходимо выполнить обратное преобразование — из таблицы с широким форматом записи данных сделать таблицу с длинным форматом. Например, для анализа данных коллеги представили сводную таблицу с затратами на рекламные источники по месяцам:

```
# Создадим исходный датафрейм:
data = {
    'source': ['source_a', 'source_b'],
    'январь': [78454, 54750],
    'февраль': [88997, 74521],
    'март': [45450, 55004]
}
df = pd.DataFrame(data)

# Выведем датафрейм на экран:
print(df) 
```

```
     source  январь  февраль   март
0  source_a   78454    88997  45450
1  source_b   54750    74521  55004 
```

Анализировать такой датафрейм (например, визуализировать данные по месяцам) не совсем удобно. Поэтому приведём его к длинному формату, где будут следующие столбцы: `source` название источника, `month` — месяц и `costs` — затраты. Для этого используем метод pandas `.melt()`. Этот метод создаёт из нескольких столбцов исходного датафрейма два столбца — один будет содержать названия признака или параметра, а другой — его значение. Как раз то, что нужно для длинной таблицы!

Метод `.melt()` имеет следующие параметры, часто используемые для создания длинной таблицы:

- `id_vars`: названия столбцов — наблюдений;
- `value_vars`: названия столбцов, которые необходимые трансформировать в формат длинной таблицы;
- `var_name`: название столбца с перечислением параметров;
- `value_name`: название столбца с значениями.

Применим этот метод для нашего случая:

```
# Преобразуем широкий датафрейм в длинный:
df_long = df.melt(id_vars='source', 
             value_vars=['январь','февраль','март'],
             var_name='month',
             value_name='costs')

# Выведем датафрейм на экран:
print(df_long) 
```

```
     source    month  costs
0  source_a   январь  78454
1  source_b   январь  54750
2  source_a  февраль  88997
3  source_b  февраль  74521
4  source_a     март  45450
5  source_b     март  55004 
```

Результат — длинная таблица. Теперь данные можно обработать и проанализировать (например, построить barplot). При работе с методом `.melt()` можно не использовать параметр `value_vars` — тогда метод по умолчанию трансформирует значения всех столбцов, кроме указанных в параметре `id_vars`.

Преобразовать широкую таблицу в длинную можно также с помощью другого метода pandas — `.stack()`. Этот метод противоположен методу `.unstack()`: на основе широкого датафрейма — создаёт длинный. Алгоритм создания длинного датафрейма будет обратный, как в случае с методом `.unstack()`:

- сначала необходимо назначить столбец, значения которого являются наблюдениями, в нашем случае — это название источника `source`, в качестве индекса датафрейма;
- затем следует применить метод `.stack()`

В результате значения всех столбцов будут трансформированы в два столбца:

```
# Назначим новый индекс:
df_long = df.set_index('source')

# Создадим длинную таблицу:
df_long = df_long.stack()

# Выведем реузльтат на экран:
print(df_long) 
```

```
source           
source_a  январь     78454
          февраль    88997
          март       45450
source_b  январь     54750
          февраль    74521
          март       55004
dtype: int64 
```

В результате была сформирована серия значения, содержащая мультииндекс. Чтобы перевести эти данные в датафрейм, сбросим индексы:

```
# Сбросим индексы:
df_long = df_long.reset_index()

# Выведем датафрейм на экран:
print(df_long) 
```

```
     source  level_1      0
0  source_a   январь  78454
1  source_a  февраль  88997
2  source_a     март  45450
3  source_b   январь  54750
4  source_b  февраль  74521
5  source_b     март  55004 
```

Осталось переименовать названия столбцов:

```
# Назначим новые имена для столбцов:
df_long.columns = ['source','month','costs']

# Выведем датафрейм на экран:
print(df_long) 
```

```

0  source_a   январь  78454
1  source_a  февраль  88997
2  source_a     март  45450
```

Какой код позволит преобразовать широкую таблицу в длинную с такими итоговыми столбцами: `player_id`, `purchase_id`, `variable`, `value`.

## Объединение таблиц
В прошлом уроке вы разобрали, что данные могут быть представлены в виде широкой или длинной таблицы. Каждый формат представления данных оптимален для решения различных задач и аналитику важно уметь проводить трансформацию данных из одного формата в другой.

Но данные не всегда хранятся в полном объёме в одной таблице, широкого или длинного формата. Как правило, базы данных, содержащие всю важную для анализа информацию, состоят из множества таблиц. Каждая таблица хранит только определённую информацию. Например, если база данных содержит информацию об активности клиентов приложения, то в одной таблице будет содержаться информация о клиентах — их идентификационный номер и основная информация. В другой таблице будут записываться их действия, в ещё одной таблице — расшифровка действий (например, совершённые покупки). Таблиц может много — всё зависит от данных, которые собираются.

При анализе данных удобно, когда все они собраны в одной таблице — с ней проще совершать агрегацию и фильтрацию значений, а также визуализировать результаты. Поэтому в своей работе аналитики часто собирают необходимые данные из различных таблиц в одну.

В этому уроке вы разберете:

- плюсы хранения данных в отдельных таблицах и создания общих таблиц для работы;
- основные принципы объединения данных из разных таблиц с помощью метода `.merge()`;
- как добавить столбец к существующему датафрейму при помощи метода `.join()`

### Нормализация и денормализация данных

Аналитики работают с разными данными. Они могут быть достаточно простыми — состоять из нескольких столбцов (например, динамики изменения суточной температуры воздуха в регионе) или содержать большой объём информации (например, фиксация действий пользователя в приложении маркетплейса).

Чем больше данных, тем сложнее становится их хранить — их объём постоянно увеличивается, количество столбцов растёт по мере добавления признаков или расчёта метрик. Данные в таких таблицах могут дублироваться и могут возникать различные ошибки в записи. В результате может оказаться, что часть данных большой таблицы становится неактуальной.

Чтобы избежать проблемы хранения больших данных, дата-инженеры используют подход, разбивающий большой объём данных на фрагменты — небольшие логически связанные таблицы. Например, одна таблица содержит уникальные данные о пользователе — его имя, почту, телефон и уникальный идентификатор региона. Другая таблица содержит информацию о регионе. Ещё одна таблица содержит информацию о действиях клиента в приложении. Информация о купленных товарах хранится в другой таблице, а информация в действующих рекламных компания в ещё одной. Таких таблиц может быть много и все они охватывают большое разнообразие действий пользователя или его характеристики.

Такой подход к хранению информации получил название **нормализации данных**. Создание отдельных таблиц минимизирует дублирование информации, а также сокращает объём занимаемой данными памяти.

Однако проводить анализ данных на Python и pandas, когда интересующие значения разбросаны по разным таблицам, может быть не так удобно и эффективно, как проводить анализ с использованием одной или нескольких таблиц. Например, если нужно провести анализ активности пользователей в приложении в разрезе региона, то хорошо, когда данные об активности пользователей, наряду с идентификатором пользователя, содержат и название его региона или его идентификатор. Так вы сможете агрегировать данные по этому признаку и достичь необходимых результатов.

Поэтому при получении задачи аналитик оценивает исходные данные и рассматривает алгоритм создания одной или нескольких таблиц, необходимых для работы. Создание из нескольких нормализованных таблиц одной большой таблицы с нужной информацией называется **денормализацией данных**.

На заметку

Во многих примерах или задачах, рассматриваемых в курсе, использовался один источник данных, содержащий всю необходимую информацию.

### Принципы объединения таблиц

В зависимости от данных и поставленных задач, существует несколько принципов объединения таблиц. Рассмотрим их на небольшом примере. Есть две таблицы: в одной таблице `users` находится информация о посетителях интернет-магазина, а в другой таблице `orders` — количество покупок. Обратимся к данным:

```
# Загрузим библиотеки:
import pandas as pd

# Создадим два датафрейма:
data_users = {
    'user_id': ['667','235','735','468','931','137','341','386','181'],
    'name': ['Петров','Громыко','Лидова','Сергеев','Дмитриев',
             'Голубева','Иванов','Сидорова','Репин'],
}
users = pd.DataFrame(data_users)

data_orders = {
    'user_id': ['667','111','735','468','931','221','341','386','456'],
    'orders': [12,3,18,8,9,3,5,7,11],
}
orders = pd.DataFrame(data_orders)

# Выведем датафреймы на экран:
print(users)
print(orders) 
```

Сейчас данные о покупках и о посетителях распределены среди двух таблиц. Это затрудняет их анализ. Например, если мы хотим посмотреть, какие пользователи из таблицы `users` сделали заказ, то без объединения данных не обойтись, поскольку информация о пользователях, которые сделали заказ, находится в таблице `orders`.

Объединяемые таблицы могут различаться по количеству записей, по сортировке данных, по столбцам. Поэтому первое, что необходимо знать перед объединением таблиц — какое значение или несколько значений использовать для объединения. Эти значения должны содержаться в двух таблицах и быть уникальными для каждой из таблиц, а для группы значение — уникально должно быть их сочетание. В нашем случае — это номер пользователя `user_id`. При этом, эти значения могут иметь различное название столбца в разных таблицах, например `user_id` в одной таблице и `id` — в другой.

Для анализа поступили данные о событиях пользователей в приложении. Есть две таблицы.

Одна таблица называется `users` и содержит такие столбцы: `id` — идентификатор пользователя, `region` — регион пользователя, `device` — устройство пользователя.

Вторая таблица с событиями `events`, содержит такие столбцы: `user_id` — идентификатор пользователя, `event_name` — название действия пользователя, `event_start_dt` — время начала события, `event_finish_dt` — время окончания.

По какому ключевому значению можно провести объединение таблиц?

  
Правильный ответ

`id` для таблицы `users` и `user_id` для таблицы `events`

Верно! Идентификаторы пользователя в двух таблицах содержатся в столбцах с разными названиями, поэтому следует использовать для каждой таблицы своё уникальное значение.
